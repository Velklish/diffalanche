# diffalanche — agent guide

diffalanche is a local code-review tool for a folder that holds many independent git repositories: one merge-request-style review across all of them, comments as JSON on disk, a CLI for coding agents. Requirements are in [docs/SPEC.md](docs/SPEC.md); the UI design is in [docs/design/HANDOFF.md](docs/design/HANDOFF.md) with a working prototype next to it. Read the spec section that your task names before touching code.

Rules for every change:

- **The tool never writes to a reviewed repository.** No commits, index changes, resets, or file edits; git is read through the `git` binary only. The only writable location is the data directory.
- **Server and CLI code use only APIs shared by Node and Bun.** Runtime-specific calls (`Bun.*`, Node-only modules without a Bun counterpart) are not allowed outside build scripts and `src/server/runtime.ts` — the single module that chooses between Bun's server and the Node adapter ([ADR-008](docs/adr/adr-008-diff-rendering-verdict.md)). A second such module is a new decision, not a convenience.
- **The UI follows the handoff, not the prototype line by line.** Tokens, layout, and behaviour come from `docs/design/HANDOFF.md`; the diff itself is rendered by the chosen library, and the prototype's hand-drawn diff is only a layout reference.
- **A UI change starts with the Impeccable context loader.** Before editing anything under `src/ui`, run `node ~/.claude/skills/impeccable/scripts/context.mjs --target <file>` from the repository root and follow what it loads: `PRODUCT.md`, `DESIGN.md`, and the surface brief of the screen. Tokens and visual rules come from `DESIGN.md`, the handoff stays the source of layout and behaviour, and the two never disagree — a value that changes in `src/ui/tokens.css` changes in `DESIGN.md` in the same pass. Run the skill's `audit` and `polish` on the touched surface before reporting, and name in the result every finding the pass did not fix.
- **The spec states behaviour and contracts, not components** (DA-112). Section 5 of [docs/SPEC.md](docs/SPEC.md) says what the user and the agent can do; the on-disk format, the CLI and the budgets say it in numbers. A component name, a module path or a description of how today's build works belongs to the [reference](docs/reference/README.md) or to an ADR — in the spec it reads like a requirement and goes stale like an implementation. There is no gate for this: the section's only identifiers are contract values, so a check would pass anything that keeps its prose about internals out of backticks.
- **Performance budgets are a gate.** Section 6 of the spec is checked in CI on the synthetic review; a change that regresses it is not done.
- **A comment in code is at most two lines** ([ADR-011](docs/adr/adr-011-comment-length.md)). `//`, `/* */` and JSDoc alike, in `.ts`, `.tsx`, `.css`, `.yml` and shell — say *why* in one breath and let the code say what it does. Knowledge that does not fit goes to its [reference](docs/reference/README.md) section, or to an ADR when it is a decision, and the comment left behind is the pointer. Markdown is prose and has no limit. The repository is not yet in compliance: bringing the existing comments in is DA-58, and until it closes the rule binds new and edited code.

## Tasks and decisions — backslop

The task tracker and decision log live in `docs/` and are managed with `npx github:Velklish/backslop#v0.9.0` (configuration: `backslop.json`, task prefix: `DA`). There is no task list in files: `npx github:Velklish/backslop#v0.9.0 status` prints the queue, active work, deferred work, and triage. The operating rules are in `docs/backlog/README.md`; terms are in `docs/GLOSSARY.md`. The layout version is the `version` field in `backslop.json`; update backslop with `npx github:Velklish/backslop#v0.9.0 upgrade` when you decide to, not because of someone else's commit.

**Skills (when an adapter is selected):** `backslop-task` — the lifecycle of one task; `backslop-batch` — a worker run by tracks; `backslop-seed` — populate documentation after installation.

**Change procedure.** There are two roles: the worker implements and verifies (steps 1–4), the approver accepts and closes (5–7); a single agent performs both roles in order.

1. **Task.** Take the first queued task (`npx github:Velklish/backslop#v0.9.0 status`) or create one: `npx github:Velklish/backslop#v0.9.0 new <slug> --title "…"` puts it in triage; `--queue` puts it directly in the queue. A small change without a tracker record is allowed if one pass fully implements it and it does not change a contract. A finding carries a cost label: fix `critical` now, fix `major` within the current task's scope now, file `major` outside it immediately with `npx github:Velklish/backslop#v0.9.0 new <slug> --parent N[.M]` and evidence, and file `minor` and hypotheses with `npx github:Velklish/backslop#v0.9.0 new <slug> --parent N[.M] --minor`.
2. **Change.** Reverse a previous decision by clean removal, without strikethroughs or “cancelled” notes. Preserve the style of the existing file. Use terms from the glossary; if a required term is missing, propose it rather than silently inventing it.
3. **Documentation in the same pass.** An undocumented change is incomplete: update the relevant `docs/reference/` section, the affected subsystem README, and CHANGELOG. An architectural decision needs `npx github:Velklish/backslop#v0.9.0 adr <slug>` and a row in `docs/README.md`.
4. **Gates before reporting.** `npx github:Velklish/backslop#v0.9.0 gates` is green: the commands in `gates` in `backslop.json`, the exit code of each, and the “gates N, green M” count.
5. **Acceptance and archive** are one approver pass: review the diff, run `npx github:Velklish/backslop#v0.9.0 archive N`, complete `result.md` (outcome, what was done, verification), and ensure `npx github:Velklish/backslop#v0.9.0 lint` is green. A worker does not declare their work accepted or move task files between directories.
6. **Triage review** follows closure immediately: every entry gets a next step — merge, clarify, `npx github:Velklish/backslop#v0.9.0 mv N queue`, or `npx github:Velklish/backslop#v0.9.0 mv N deferred` with a return condition. Ask the owner only before rejecting an entry.
7. **Commit.** Start the message with the task number: `DA-N: <what was done>`. A task reaches the main branch as one commit: taking it, review fixes, and acceptance are squashed before pushing.

Worker boundaries: change only the assigned branch or worktree; do not touch status directories or `docs/archive/`; closure and triage belong to the approver.
