# DA-81 · Result

**Closed 2026-09-18.** Completed. `--review` is declared in `GLOBAL` and merged into every command's parser, and the only thing that read it was `context.session()`, which `serve` never called. A name no session had was exit 0 with no message on `serve` and exit 1 on `list`, `diff`, `show`, `comment` and `export`. Worse than the unreported typo: `serve --review t2 --open` reads as the gesture [ADR-010](../../adr/adr-010-review-task-scope.md) makes idiomatic and was not one — `--open` opened `server.url`, so the browser landed on whatever `current` pointed at and the counters under the address were that other task's. Taken as **(a)**, the flag honoured: the flag table of `06-cli.md` says every command takes these, with `version` as the only command that reads no session, so refusing would have made `serve` a second exception and honouring it makes the table true. The server needed no change at all — `review.document()` already takes a name and the routes already take the task per request. The name is resolved through `context.session()` and **only when the flag is actually given**, because resolving unconditionally would have put `?review=<current>` into the address of every run that never asked for it; the resolution happens before `startReviewServer`, so a misspelling is exit 1 with the domain's own `no review session "…"` and no socket is left open. With the flag, the printed address is `http://127.0.0.1:<port>/?review=<name>`, the counters are that task's, and `--open` opens what was printed. `current` is not moved.
