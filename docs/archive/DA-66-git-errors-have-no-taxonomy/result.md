# DA-66 · Result

**Closed 2026-09-19.** Completed. `src/core/git/errors.ts` tells four failures apart by what Node reports, and the discriminator is the **type** of `code`: a string is the spawn's own errno, a number is git's exit code, `ERR_CHILD_PROCESS_STDIO_MAXBUFFER` is output that did not fit, and a signal is a kill. The fourth shape is not in the card and is not padding: the card calls `EAGAIN`/`ENOMEM` reachable through the unbounded fan-out, and the OOM killer takes a process down with a signal, where `code` is neither a string nor a number. What happens next is deliberately asymmetric. A repository's own fault — a non-zero exit, output too large — is one warning on that repository, and the other twenty still come back, the way the scan answers for a directory it cannot read. A machine that cannot run git is the same answer in every repository under the root, and twenty-one warnings hide it, so it is raised instead. The boundary lives in `readRepositoryChange`, which is where every caller gets it: the CLI, the server's three call sites and the watcher's one. `gitOrNull` returns `null` for a non-zero exit and nothing else. Before this it swallowed every failure, so a git that could not be started came back as `null` and became `HEAD does not resolve: no commits yet` in every repository — an empty review, a warning blaming each repository, and exit code 0. In `src/cli/run.ts` a `GitError` joins the usage, domain and storage refusals: one line and exit 1, where it was a stack trace and exit 2.

**Verification.** One verdict builds each of the four shapes and asserts the failure, the exit code and whose fault it is; one drives a real spawn failure through the reader and asserts it is not swallowed; one removes the blob HEAD needs from a repository and asserts that repository comes back with `base: null` and a warning naming exit 128, while the healthy repository beside it still answers. Mutation probes by the worker: `gitOrNull` back to a bare catch reddens the spawn verdict; the boundary disabled reddens two. Two limits stated rather than implied. `maxBuffer` is the one shape not driven through real git — the verdict builds the error object with the code Node uses, rather than producing thirty megabytes of diff. And the spawn verdict first passed on Node and failed on Bun: `PATH=""` is not a spawn failure there, because Bun falls back to a default path and finds git anyway. A `PATH` pointing at an empty directory fails on both. The Bun half of the suite ([ADR-009](../../adr/adr-009-unit-suite-on-bun.md)) is what caught it. Worker gates on `fbaf0e1`, clean tree: backslop lint 0, `bun run lint` 0 (176 files), `bun run typecheck` 0, `bun run test` 0 (35 files, 469 tests), `bun run test:bun` 0 (35, 469); `bun run perf` exited 1 on two lines at load average 33.2 and was re-measured at integration. **Integration into `main`:** `1ff6a41`, `66e91a0` and `ec191fc` cherry-picked onto the DA-73 commit.
