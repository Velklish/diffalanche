# DA-55.6 · Result

**Closed 2026-09-24.** Completed: a task made current while the server runs is read before it is followed. `reloadCurrent` (`src/core/watcher/index.ts`) reads the session `current` moves to from the working tree — `readWhole`, the same `rescanSession` the startup `refresh` of DA-55.5 runs — before it sets `session = next` and before it emits `current-changed`, so the window that re-reads on the frame is served what the read handed over, not a `diff.json` nothing refreshed. The task's metadata baseline and `scope` come from the `review.json` read once before the read, so a change to it made meanwhile is still a `session-changed`, and a session a window already follows keeps its baseline. A task with no `diff.json` is not read: there is nothing to trust, and the first document reads the working tree anyway. The repositories the read found different from the `diff.json` it replaced are announced after the frame as `diff-changed` with files `[]`, and `warnings` if they changed, with no activity line — without that, an edit the read absorbed was never announced to a window on the task by `?review=` (found by the worker while measuring, 10 of 10 edits). A read that fails goes to `onError`, and the session is followed as at startup. **Rejected:** the card's "natural answer", the read queued after the move like startup — its probe, the read enqueued after `current-changed`, turned the new server test red 3 of 3: the window's GET on the frame beat the queued read and was served the stale `diff.json`.

**The price**, measured by the worker on the full synthetic review (21 repositories, no scope, bun, native watch, alternating base and branch, busy machine — upper bounds) and written in `docs/reference/07-server.md`: a move of `current` to its frame 570 and 602 ms against 115 and 117 ms on the base; an edit made 150 ms after `review use` to its frame 433 and 520 ms against 209 and 204 ms — over the 300 ms budget of `docs/SPEC.md` section 6 in that one scenario, because the watcher's queue waits for the read. The UI's session menu does not move `current` (it moves the address to `?review=<name>`), so it does not pay it; its paired measurement showed no systematic difference. The orchestrator carries this price to the owner in the run's report.
