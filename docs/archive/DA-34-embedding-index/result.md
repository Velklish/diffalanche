# DA-34 · Result

**Closed 2026-09-24.** Completed. `src/core/ml/index` keeps a vector for every comment of every review session in `index/index.bin` of the data directory, `diffalanche index rebuild` builds it from scratch and `index status [--json]` says what it holds without loading the model; nearest-neighbour search by cosine with a session filter is brute force. Decisions this acceptance records:

- **The index is brought up to date by its reader** — `index rebuild`, and from DA-35 `suggest` and the server's `GET /api/suggest` — by the `stat` of each session's `comments.json` and then a check of each comment's id and text, so only new and edited texts are embedded. Both places the card offered were rejected, with the reasons in [09-ml.md](../../reference/09-ml.md): a hook on the domain write would load the model on every `comment` of the CLI (0.7–4.8 s and 476–650 MiB per ADR-014, and a download on the npm channel), and the event bus misses every write made while no server runs. The card's check "writing a comment updates the index" became a functional one: a comment written through the CLI with no server running, and one written through `POST /api/comments`, is each found first by the next query from a paraphrase — tested on both runtimes in `tests/embedding-model.test.ts`.
- **`index/index.bin` is one line of JSON and then the vectors as raw `float32`**, one file renamed into place so entries and vectors never disagree. The first build used JSON with base64: a query over 10 000 comments then peaked at 790 MiB on Bun, over ADR-014's 768 MiB; raw floats took it to 736 MiB.
- **The fingerprint of a session is the mtime, size and inode** of its `comments.json`. A data directory with no session refuses, as `list` does, and gets no `index/`; a `comments.json` that no longer parses keeps what was indexed of it and its old fingerprint, so the index is not rewritten for it. `index/` is outside the watcher (`dataIgnore`).
- **Catch-up and search, measured** (M1 Pro, 8 cores, shared; loads 13–17): one new comment 7–14 ms, 200 new 1.1–1.2 s with the model warm; search over 10 000 vectors 1.8 ms on Bun and 3.6 ms on Node at the median, 17.7 / 36.8 ms at 100 000. Brute force is fine to about 20 000 comments, where memory, not speed, stops it on Bun: that is [DA-34.2](../../backlog/queue/DA-34.2-bun-query-memory-ceiling-past-20k.md).
- **The files that load the model run in a vitest project of their own** (`model`), one file at a time after every other file, so one copy of the model is resident at once and none beside the watcher's timed tests. Every verdict now prints with a `|unit|` or `|model|` tag; names are otherwise unchanged — base 601, the track's tip 640, none removed.
- **The npm bundle carries no embedding runtime until DA-41**: `build:cli` keeps `embedder.ts` out, and `index rebuild` from `dist/cli.js` refuses in one line.

**Owner's decision on memory, 2026-09-24.** Given the server's memory measured under DA-35 — Bun 742 and 764 MiB, Node 659 and 657 MiB after the first `/api/suggest`, against the ceiling of 768 MiB — the owner decided to land DA-34, DA-34.1 and DA-35 now, to move the memory work to the queue, and not to change ADR-014. DA-34.2 moved from `minor/` to the queue in this commit, with the server's numbers beside the query's and the candidates to weigh; the choice among them is the owner's.
