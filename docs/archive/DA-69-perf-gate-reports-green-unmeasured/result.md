# DA-69 · Result

**Closed 2026-09-21.** Completed. The perf gate could report green on what it had not measured, in two independent ways, and both are closed. **The fixture.** Freshness was the existence of `.diffalanche/current`, and `current` exists whatever it points at — the harness's own scratch session made it point at itself, and one killed run left the fixture measuring a fifth of the specified comment load for ever, silently, on every subsequent run. `scripts/synth.ts` now stamps `synth.json` with what it actually wrote — generator, seed, profile, the session `current` names, the thread and reply counts — `prepare` reads it back, prints which field differs, and regenerates; the scratch session is named `perf-scratch`, a name that cannot compose with itself, and is rebuilt when it does not hold what the run would write, built *after* the current session's change set exists rather than before, which is what makes every repetition measure a switch into a session with forty comments instead of the first one measuring an empty rail. **The verdict.** A line whose samples cannot be trusted said `ok`, because `NaN > 500` and `0 > 8.3` are both false. There is now a third verdict, `UNMEASURED`, which prints and exits 1 — a verdict rather than an exception, so one missing metric leaves the rest of the table readable — and untrusted means absent, non-finite, or, on a millisecond line only, exactly zero. The zero rule is the judgement of the pass and is recorded as one: no step of this harness takes no time, while a count of zero long tasks is the goal of its line. A missing `TaskDuration` now throws where it can be named instead of standing in as a CPU-per-frame of 0. **The stamp order**, found in the second review round: the generator wrote `synth.json` last, so a `bun run perf` killed inside `synth` left the fixture non-empty and unstamped, and DA-63's erase guard — which reads that stamp — then refused every later run, turning a directory the gate had created under its own default name into a dead end. The stamp is now claimed immediately after `mkdirSync` with the generator, seed and profile, and rewritten whole at the end with the session and its counts; `session` and the counts are optional in `FixtureStamp`, and their absence is precisely what `fixtureDrift` reads as an unfinished run and what lets the gate regenerate.
