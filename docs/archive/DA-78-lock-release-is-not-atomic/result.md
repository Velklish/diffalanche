# DA-78 · Result

**Closed 2026-09-18.** Completed. `release` in `src/core/storage/lock.ts` is written on the primitive `takeOverIfStale` already uses: the lock directory is renamed aside to `.lock.released-<uuid>`, the token is read from the moved directory, and that directory is what gets deleted — so a writer whose body outran its lease can no longer remove the live lock of the successor that took the session over. A lock that turns out to belong to somebody else is renamed back; `ENOENT` on the move is the ordinary case after a takeover and passes silently; a moved directory with no `info.json` is removed, with the same answer a takeover gives. The rename-aside was chosen over the task's other candidate — an unconditional release reachable only while the lease has not expired — because comparing clocks is not a synchronisation primitive: a body that outlives its lease still reaches the conditional branch, so that variant hides the case this task was filed for instead of closing it. The price is one extra syscall on an uncontended release, on the path every write ends with, and one window that stays open: between the two renames a third writer that manages a `mkdir` in the slot keeps the lock, and the writer it displaced learns that from `assertHeld` before it writes rather than losing the write. That is the same trade-off `takeOverIfStale` takes in its own "rename back failed" branch, and it is named in the reference.
