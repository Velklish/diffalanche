# DA-8 · Result

**Closed 2026-09-05.** Completed. `src/core/storage/` is the only module that reads and writes the session files of the data directory: path helpers (`dataDirOf`, `sessionDir`, `reviewPath`, `commentsPath`, `diffCachePath`, `currentPath`), `ensureDataDir` / `ensureSessionDir`, typed read and write of `review.json`, `comments.json`, `diff.json` (envelope only; the change set is core-a's contract) and `current` (defined here as one line with the session name plus newline; the fixture generator writes it too), JSON with `version: 1`, two-space indentation and a trailing newline, schema validation on read with `StorageError { file, field }`, atomic writes (temp file with a `randomUUID` suffix in the same directory, `fsync`, `rename`), `withLock(sessionDir, fn, options)` with `mkdir` of `.lock`, backoff 5→100 ms, a 10 s wait budget, stale takeover after the `expiresAt` the holder wrote (30 s) by renaming the stale directory aside (atomic, so two waiters cannot both win) and a `Lock.assertHeld()` the body calls before writing, `updateComments` as the read-modify-write path that also bumps `updatedAt` in `review.json` under the same lock, and `listSessionNames` with warnings for directories without `review.json`. Session names are validated at the file-system boundary: a single path segment, so a hand-edited `current` cannot steer writes into a reviewed repository.
