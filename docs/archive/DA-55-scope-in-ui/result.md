# DA-55 · Result

**Closed 2026-09-10.** Completed, and larger than the card asked. The screen carries the task: a `SCOPE` pill beside `BASE`, an editor over the whole candidate list from `GET /api/sessions/candidates`, a confirmation that names the file and counts the comments before anything is destroyed, a `select` tab that turns the tree into a picking surface with `New task…` under it, and a window that takes its task from `?review=<name>`. Switching a task changes this window's URL and leaves `current` where the human put it.

**The task had to finish what DA-53 started, and that is the half worth remembering.** DA-53 gave `?review=<name>` to one route — `GET /api/review` — and left the rest of the window on `current`. In that state a window on `?review=X` read X and **wrote to Y**: a person's comment landed in `reviews/Y/comments.json`, `Resolve` reached another task's threads, the export produced Y, and live update patched X's screen with Y's change set. That is review data going to the wrong place, and it made the card's own line — switching does not move `current` — actively harmful rather than merely unimplemented. So seven more routes and `repository()` learned the task's name through one helper, `POST /api/sessions` learned `scope` and `use`, and the contract is written down in `docs/reference/07-server.md`. Without the parameter every route still answers about `current`.

Two owner decisions were taken during the pass. Creating a task does not move `current` — **except** the first review created from the empty-state screen, where `current` does not exist at all and the CLI has no default to fall back on; the exception is written into ADR-010 beside decision 4 and held by a test on both branches. And the repository name on a thread card stands first, because the fix for the dead chips needed the whole header inside one focus button and the repository jump can neither nest in it nor split it.

**Three defects were found by measuring rather than by reasoning, and each measurement said something different from what was expected.**

A window on a named task answered a live update *faster* than one on the current session — 253 ms against 275 — and the reason was that it was answering with nothing: the card of the edited file never showed the edit, three times out of three. The watcher rewrites `diff.json` for `current` only, so a task that is not current holds a change set frozen at its last read, and the page had nothing to apply. `freshRepository()` now reads that one repository from the working tree, filtered by the task's scope, at the cost of the four git processes the watcher pays for the current session anyway. The other half — the *document* of a named task, built from the same cache — is [DA-55.3](../../backlog/queue/DA-55.3-named-task-document-is-stale.md).

Switching sessions measured 149 ms against a 100 ms budget, up from 109 on the base. `showTask` was setting `status: "loading"` before loading, which put the skeleton between two reviews and unmounted three hundred cards to mount three hundred more. Removing the status change took it to 89.8 — better than the base. It was caught only because the branch and its base were measured side by side.

The unit suite went red on the merge commit while the base stayed green, which pointed straight at this task — and was wrong. The failure is a race that had been in `tests/watcher.test.ts` from the start: `fs.watch(recursive: true)` arms after it returns, and a write made in that window is lost outright. The tell was in the green runs, which print 318, 327 and 339 ms: no load turns a third of a second into twenty seconds, so the event was never arriving rather than arriving late. An A/B probe on one fixture gave 4 misses in 30 without a warm-up and 0 in 30 with one — 13% a run, which is also why three green base runs proved nothing. `arm()` now repeats the write until the watch answers, because no timeout recovers a lost write; the repository already knew this and applied it to `supportsRecursiveWatch` only.

**Verification.** Six gates, run by the approver on the merge commit rather than on the worker's branch: `backslop lint` 0, `bun run lint` 0, `bun run typecheck` 0, `bun run test` **0, 0, 0** across three runs (463 tests each), `bun run test:bun` 0 (463). `bun run test:ui` 0, 73 tests — not a gate, and the only thing that sees this screen at all ([DA-54.2](../../backlog/queue/DA-54.2-ui-suite-in-gates.md)). **`bun run perf` was not run: the owner moved it to a single pass after all four tasks.** Five of six, not "all green".

Every line of the card's verification has a test in `e2e/scope.spec.ts` or `tests/write-api.test.ts`, and the two that matter most assert absence rather than presence: the third repository is missing from `.workspace` rather than hidden by CSS, and cancelling the confirmation leaves `comments.json` byte-identical. An isolated reviewer read the diff and raised eight findings, all closed. The heaviest was structural: two overlays were mounted at once, `Overlay` listens for Escape on the document, and one Escape closed both — losing the draft the documentation promised to keep, while two focus traps fought each other and froze Tab inside the one dialog that destroys data. The confirmation now replaces the editor, and a mutation probe confirmed the old rendering did close both.

**Documentation in the same pass.** `docs/design/HANDOFF.md` (1.1, 1.3, and section 12 for the editor and its confirmation), `.impeccable/surfaces/src-ui-app-tsx.md`, `docs/reference/08-ui.md`, `docs/reference/07-server.md`, `docs/reference/05-watcher.md` (the arming rule and the A/B numbers), ADR-010, `docs/SPEC.md` §5, `docs/GLOSSARY.md`, `DESIGN.md` (the `Danger` button), `CHANGELOG.md`.

**Left open.** One red `bun run test:ui` did not reproduce: `e2e/live.spec.ts:106` received 44 against a bound of 22 at a load average of 14.8, and was green in five other runs, twice alone, once under a deliberate 19.2, and on the base at 43.4. 44 is two diff rows, so it means no correction ran at all rather than one that fell short — which is why the number matching DA-54's earlier failure was not evidence. The sticky-anchor cause of DA-54 was ruled out by probing `elementFromPoint` in four states: `.file-head`, static, no sticky ancestor up to `.centre`.
