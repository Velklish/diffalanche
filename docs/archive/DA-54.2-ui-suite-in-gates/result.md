# DA-54.2 · Result

**Closed 2026-09-21.** Completed. The Playwright UI suite — the sidebar, the thread rail, live update, the repository bar — ran only when somebody typed `bun run test:ui`, so a UI regression could reach the main branch through six green gates and a green CI, and one had. It is now the **sixth entry of `gates` in `backslop.json`**, placed between `bun run test:bun` and `bun run perf` so that the two browser gates are adjacent, and the `ui` job of CI runs `bun run test:ui:ci` — the same suite with `--ignore-snapshots`, because the screenshot baselines were taken on macOS and a Linux runner draws other pixels. The collision that the two Playwright configurations document is handled structurally rather than by convention: each worker has its own worktree and therefore its own `dist/`, `backslop gates` runs its commands one after another, `test:e2e` is not among them, and in CI the two are separate jobs on separate runners. Two things had to be fixed to make the suite gate-worthy. **The port.** It held a fixed 4881 with `reuseExistingServer` off — right for one person running it by hand, wrong for a gate, since two workers on one machine could not both pass it and the second got `port is already used`, a red gate with nothing behind it. A worktree per worker separates `dist/`; the loopback interface belongs to the machine. It now binds port 0 in a child process the way `e2e/acceptance.config.ts` does, pins the number in `DIFFALANCHE_UI_PORT` for the workers Playwright forks, and passes it to `e2e/server.ts`. **The screenshots.** The sidebar footer prints `127.0.0.1:<port>`, so the free port above moved four digits of monospace text and both shell baselines failed on 33 pixels of 1.4 million — a regression of the suite introduced by the fix beside it, invisible on CI because the `ui` job runs with `--ignore-snapshots`. The footer is masked, for the same reason `/api/activity` is stubbed in that file: a baseline may only carry what does not vary. Its text stays covered by direct assertions in six specs, `shell.spec.ts` among them, and the two baselines were re-shot with the mask in place.

**Verification.** Mutation probe 5 of the track is this card's own acceptance — the card asks for a UI spec broken on purpose with the chosen gate watching. `src/ui/measure.ts:61`, made to count a wrapped line as one row, on `a009129`: `bun run test:ui` exit 1, **90 passed of 95**, five specs red in three files — `diff.spec.ts:84`, `repo-bar.spec.ts:85`, `repo-bar.spec.ts:204`, `wrap.spec.ts:197`, `wrap.spec.ts:227`; `git status --porcelain` empty at both ends. The probe touched `src/ui/measure.ts`, a file belonging to the `sessions-cache` track, for the length of one command inside this worker's own worktree; the orchestrator was told and confirmed it was within the rule. The suite itself is green in the gate chain, 95 of 95, exit 0. **The card's own numbers were wrong and are corrected here rather than quietly matched**: it said 65 tests and 37 seconds; measured on 2026-09-21 the suite is **ten spec files, 95 tests, 71–78 s for the whole command** — the UI build, the fixture, the server and the tests together — and 93 s at a load average of 43.

**Two decisions of the run, recorded so nobody re-opens them.** First, the 27-line block of required check-run names in `.github/workflows/ci.yml` was **left uncompressed despite [ADR-011](../../adr/adr-011-comment-length.md)**. Second, and this one is not closed by any file: **`UI suite` still has to be enabled by hand in branch protection.** A workflow file cannot add itself to a repository's required check runs, so until somebody with the setting open does it, the new job runs and reports but does not block. The orchestrator carries that to the owner.
