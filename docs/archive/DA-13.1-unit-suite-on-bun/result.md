# DA-13.1 · Result

**Closed 2026-09-05.** Completed. The finding held: `bun run test` starts Vitest through Bun but Vitest runs the tests on Node (`process.execPath` is the Node binary inside a test, `process.versions.bun` undefined). Vitest 5 runs on Bun's runtime with `bunx --bun vitest run`, the whole suite green there and faster (246 tests: 11.0 s on Bun vs 15.0 s on Node in one loaded pair, 8.9 s vs 10.1 s in a quiet pair). Decision, recorded as [ADR-009](../../adr/adr-009-unit-suite-on-bun.md) (revising ADR-006's "the whole unit suite twice is slow and mostly redundant"; ADR-006 and ADR-008 carry two-way revision notes): the whole suite runs on both runtimes — `bun run test:bun` (`DIFFALANCHE_TEST_RUNTIME=bun bunx --bun vitest run`), CI job `test-bun` on ubuntu, `bun run test:bun` in `gates`; `tests/runtime.test.ts` asserts the runtime that executed the suite against `DIFFALANCHE_TEST_RUNTIME` (default `node`) with a message naming the variable and the command; both CI jobs print their runtime (`process.versions`) before the suite. The `engines` half was settled with DA-14 (`>= 22` for the bundle, 22.18 as the development floor).

Review by an isolated session, two rounds: six minor (245 vs 246 in the two documents; the runtime not printed in CI; the bare `expect`; `test:bun` missing from `gates`; the 11-perf title and index row; the one-way ADR link) — closed in `b7bb04a`.
