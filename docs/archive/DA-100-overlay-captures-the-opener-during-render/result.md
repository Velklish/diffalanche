The opener belongs to a **ladder**, not to an `Overlay` instance. `Overlay` takes a `ladder` prop: `scope` for the editor, its confirmation and the new-task form, which occupy one position in `App.tsx`, and one of its own for the base picker, the export and global search, which cannot swap with anything. The first overlay of a ladder records `document.activeElement`, a swap keeps it, and the restore is owed once the ladder has emptied. The render-time read the card defends is kept — a child that focuses itself as it mounts would otherwise be the opener — and what changed is that it is recorded once per ladder rather than once per instance. That is what the round-trip broke: each swap recorded the button it was replacing, and the last overlay to close restored a node detached two commits earlier, doing nothing at all. **Which restore is owed, and when:** a count of mounted overlays per ladder, read **after** the commit. The first version cancelled a pending restore from the arriving overlay's render, and React renders the arriving overlay before it cleans up the leaving one, so the cancel was spent before the cleanup that needed it and the swap restored anyway. The new test said so before anything else did.
