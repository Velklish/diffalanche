# DA-56 · Result

**Closed 2026-09-10.** Completed. The sessions menu became the history of review tasks: two groups — `Открытые задачи` above `Закрытые` — each ordered by `updatedAt` as the server already returns them, so the split is a filter and never a sort. Each row carries its scope as a chip counted by the same `countScope`/`scopeLabel` the `SCOPE` pill uses, or `все репозитории` when a session has none, and closes or reopens from the row through the routes DA-53 built. A quiet dot on the session pill says a task appeared while the window was open; it raises nothing else — no toast, no reload, no scroll, no closing of an open composer — and opening the menu clears it. The window's own writes do not raise it.

`current` moves nowhere: the close and reopen routes take the name in the path, sign with `config.user` and `role: human` on the server, and the row shows **two** chips rather than one — `ЭТО ОКНО` for the task this window is on, `CLI` for the pointer a terminal without `--review` would use. The word `CURRENT` appears nowhere in the product: in a list of tasks it reads as "the main one", and decision 7 of [ADR-010](../../adr/adr-010-review-task-scope.md) says there is no main task.

Two things were renamed or restructured because this change made them ambiguous, not to improve them. The row's existing metric became `N repos changed` — the scope chip beside it now also counts repositories, and the two diverge exactly when a file in the scope stops changing, which is decision 5 working as written; `docs/reference/08-ui.md` says when they part and forbids reconciling them. And the mark reuses `.dot.acc` rather than a shape of its own, after review found a 6 px circle where `DESIGN.md` says "Nothing is a circle except the 7 px status dots" — a second round primitive and a contradiction between `HANDOFF` and `DESIGN.md` in a pass that had declared itself clean.

Five of six, and the sixth is [DA-56.3](../../backlog/queue/DA-56.3-perf-pass-over-the-package.md). `bun run test:ui` — the only thing that sees this screen — ran 77 tests; the history mark measured 246, 234, 273, 258, 236 and 185 ms across the session against a 300 ms live-update budget.

Nine mutation probes across two rounds, all red, each preceded by the line its script prints only after the replacement actually applied — a guard added because the first round's five probes had all failed to patch anything and passed against untouched code. The most telling was `scope-chip`: without the `null` branch the chip showed **`0 repos`** for a session about the whole root — not an error, a plausible number, the kind of line that survives reading and review and is caught only by a test that knows the answer.

An isolated reviewer raised five findings, all closed and each held by a probe that goes red. Beyond the circle above: `CURRENT` still standing in `DESIGN.md`'s tag examples; focus falling to `<body>` inside an open popover after a close; `1 repos changed` unpluralised beneath a chip that pluralises; and a test whose comment promised to cover the double-frame case while creating a task that produces one frame — so the two-part `selfWrites` key, the thing that test existed for, was covered only by a unit test of the key itself. That is now closed on a real current task, and the probe proves it.

Accepting this task on merged main also surfaced a defect in **DA-55's** already-accepted fix: `arm()` cured the lost-write race but separated the removal of its probe file from the first test with a fixed 300 ms sleep — in a file whose own `settle()` helper documents why a sleep is wrong. `arm(OTHER_REPO)` runs last, so its removal event could arrive after the sleep and be caught by the first test as its own: `expected 'repos/platform/loads-search' to be 'repos/core/cargos-api'`, in 21 ms, once in six runs. It now waits for the removal's own event. Ten full runs went green at load averages rising from 15.5 to 26.4 — which, at a rate near one in six, is an absence of failure rather than proof of absence; the weight is structural, because the wait cannot report success without having observed an event, and a sleep always can.
