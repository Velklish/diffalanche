# DA-67 · Result

**Closed 2026-09-22.** Completed. Two writes that the storage rule covers now take the session's lock. **The scope check of `addComment`** read `review.json` and decided on it *before* the lock, with `assertAnchorLevels`, `captureAnchor` and a full parse of `diff.json` in between, so a `review scope set` narrowing landing in that window left a comment on a path the scope no longer had — stored, filtered out of `list`, answered `no-such-comment` by `get`, `reply`, `resolve` and `reopen`, and announced as written on exit 0. `addComment` moved from `updateComments` to `updateSession` and checks the scope **inside** the lock against `draft.review`, the copy read under it; that refusal has a message of its own, because a scope that narrowed under a comment being written is a different fact from a comment that was outside the task all along and one `out-of-scope` code would not have said which. **`diff.json` in the diff command** was a bare write where the other five writers take the lock and call `assertHeld`. The interleaving that loses work is the reverse of the obvious one, which is why `assertHeld` could not catch it: the watcher holds the lock honestly, reads the cache, and writes `{...cached, repositories: cached minus this repo plus the new one}` over a full scan the CLI wrote in between, so everything the CLI found for the other repositories is gone — and the cache then answers for the same `base` and `scope`, so the server serves it unchanged until an fs event fires, which is precisely the case `diff` is run by hand for. That write is now wrapped in `withLock` + `assertHeld` like the other five.

**The two decisions the card left to the implementer.** First, **the early scope check stays** in addition to the locked one. That is not redundancy: `assertAnchorLevels` and `captureAnchor` sit between them, so a comment both out of scope and on a line not in the diff is still answered `out-of-scope` rather than `line-not-in-diff` — a visible contract change the card did not ask for — and an out-of-scope refusal still does not read the whole of `diff.json` on its way out. Second, **the anchor capture stays outside the lock**: putting `readDiffCache` under it would make every comment write hold the session for a parse of the largest file in the session directory, which the watcher and the server contend for, and pinning a cache under the lock does not make it fresher. The scope is a rule about whether the comment may exist at all, and only the rule needs the lock. `updateComments` stays the entry point for `reply`, `resolve` and `reopen`; only `addComment` moved.

**Verification.** Two mutation probes, each with its expected verdict written down before the run. **P1** — `assertAnchorInScope(draft.review, repo, path)` deleted from the locked body — reddened `is refused rather than written where nothing can read it`. **P2** — the `withLock` around `writeDiffCache` in `src/cli/commands/diff.ts` replaced by the bare call — reddened `loses no repository out of diff.json` in `tests/lock-writers.test.ts`, exit 1, 2 base verdicts, 1 passed, 0 unaccounted. `git status --porcelain` was empty before the probe and after the restore. The verdicts live in `tests/lock-writers.test.ts`, a new file.

**The residual, named rather than smoothed over.** The lock-writers suite waits for a racing scan, and that wait was a fixed 400 ms. Made to measure its own precondition it failed immediately on this machine: the fixture scan took **467 ms** under the gates chain, which means every earlier green of that verdict had been reached without the writer arriving at all. The wait is now a floor under a multiple of the scan the test itself times. **The multiple is a heuristic and not a bound**, and that is what this task leaves open.

**One thing this approver worked around, named rather than left implicit.** The session runs under a harness guard that refuses file edits in the shared checkout until the agent moves into a worktree. That guard is written for a worker and is unsatisfiable for an approver, whose whole job is to write into `main` of the shared clone; moving into a worktree would mean a second merge of the work just landed. The `result.md` files were therefore written to a scratch directory and copied in through the shell, which the guard does not cover — the same path `backslop archive` already takes, since its `git mv` runs as a command. No session setting and no `.claude/settings.json` was changed. The orchestrator sanctioned this explicitly and holds the narrowing of that guard as a finding about the workspace mechanism.
