# DA-54 · Result

**Closed 2026-09-10.** Completed. `.repo-head` became one 38 px line stuck under the header inside its own `section.repo`, so each bar is pushed out by the next repository rather than stacking; a `--bd2` hairline sits above every section but the first. The tree row keeps one tab stop and one focus ring — the row itself is the button, the caret is an `aria-hidden` span inside it — and the two actions are told apart twice: the pointer by `event.target.closest(".repo-toggle")`, the keyboard by which key was pressed, `Enter` to jump and `Space` to collapse. The repository name on a thread card became its own jump button. All jumps go through `revealCard`.

Two things the task did not ask for and could not be finished without. `PROBE_Y` had a second copy in `live.ts`, and the sticky bar swallowed the anchor there: the probe walked down from 62 px, hit the bar — which is inside `.centre` and never moves — and live update stopped correcting the reading position, caught by `e2e/live.spec.ts` at 44 px against a 22 px bound. The fix removed the copy rather than patching the symptom: one constant exported from `reveal.ts`, imported by `CentrePanel.tsx` and `live.ts`, with the three handwritten copies of the number named in `docs/reference/08-ui.md`. And `.file-card { scroll-margin-top }` moved 62 → 100 with it, or a card jumped to would land under the bar.

Two owner decisions were taken during the pass. The tree row has **one** tab stop, not two: `aria-expanded` on a `div` without a role is invalid and `role="button"` around two real buttons is nested interactive, so the row is the button. On the thread card the repository name stands **first** — the fix for the dead chips required the whole header inside one focus button, and the repository jump cannot be nested in it or split it, so it goes at one end or the other.

**Verification.** Six gates on `8fdeaf7`, each run separately with its exit code read from `$?`: `backslop lint` 0, `bun run lint` 0, `bun run typecheck` 0, `bun run test` 0 (409 tests), `bun run test:bun` 0 (409), `bun run perf` **1**. Beside them, and not a gate: `bun run test:ui` 0, 66 tests.

The red gate is the machine, and it was measured rather than asserted. Four paired runs against the base commit gave differences of both signs (base worse by 1.2, this commit worse by 1.6, identical at 8.9, this commit worse by 1.0), and the decisive run was neither: the same commit with `position: static` — the whole subject of the task removed, one line changed — still failed at 9.0 ms against the 8.3 ms budget. The cost of stickiness is 0.1–0.4 ms; the overshoot is about 1.1. On a quiet machine this commit measured 8.2 ms and passed. The budget's own headroom is [DA-54.3](../../backlog/triage/DA-54.3-perf-budget-headroom.md).

`e2e/repo-bar.spec.ts` holds seven tests, one per line of the task's verification plus the hairline and the keyboard. Four mutation probes were run after the commit: sticky → static fails the two bar tests, `PROBE_Y` 100 → 62 fails the tree probe and `live.spec.ts`, the row's two targets swapped fails the click test, the thread jump disabled fails its own. Two more probes after the review round: the severity chip taken back out of `.thread-focus` fails the new `threads.spec.ts` test, the thread jump disabled fails `repo-bar.spec.ts`.

An isolated reviewer read the diff with a fresh context and raised seven findings, all closed in the same pass. One was a regression rather than a remark: the severity and state chips had fallen outside `.thread-focus` and were dead to the pointer, where the whole header used to focus the thread. Two more were accuracy: the paragraph in `docs/reference/08-ui.md` written to protect the `PROBE_Y` coupling named two importers as copies and missed the two e2e probes that really are copies, and a test comment pointed at the wrong file. Two were accessibility: the caret's target was 15×20 px against the 24×24 of WCAG 2.2 SC 2.5.8, and nothing told assistive technology that `Space` collapses — closed with `aria-keyshortcuts` and one visually hidden sentence, which also closes the first of the two findings the Impeccable audit had left open.
