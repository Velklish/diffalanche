# DA-68 · Result

**Closed 2026-09-22.** Completed. Session identity travels with the live frames and with the store's loads, so a window on a task no longer reacts to another session's events. Three places in the page assumed there was only one review — the comment frames, the diff patch and `loadReview` itself — and none of them carried the name of the task the data belonged to, while all three are reachable from one window. Since DA-55 a window can be opened on a task that is not `current`, and decision 7 of ADR-010 makes that the normal case rather than the exception.

**The critical regression this task first introduced, and why the fix is a frame split rather than a revert.** The first attempt narrowed the `session-changed` guard to the review on screen. That stopped an address-less window from following `current` **while it kept writing to `current`** — a comment written from the screen showing A would land in B with an anchor taken from A. The two-line revert was refused: after [DA-55.1](../DA-55.1-watcher-follows-one-session/result.md) every followed session emits that frame, so letting it through for the address-less window would re-read the review on any watched session's change, which is exactly what ADR-010 forbids. The fix is to split the frame — `current-changed` for "the pointer moved", `session-changed` for "a followed task's metadata changed". **This is not a widening of the task**: a frame that means two things does not carry its identity, which is DA-68's whole subject. The window without an address follows the first; the window with one ignores it. The emitter half of the split is in DA-55.1's commit, because at DA-55.1 the watcher already emits the new frame and the old tests would be red without it; the reader half is here — `src/ui/live.ts` gains the `current-changed` handler and the on-screen guard on `session-changed`, and `tests/ui-stream.test.ts` gains the three verdicts.

**Verification.** A mutation probe with its expected verdicts written down before the run: `src/ui/live.ts:132` broken on a clean committed tree, `git status --porcelain` empty before and after the restore, 574 of 576 verdicts passing and **the two reddened being exactly the two expected** — "a comment frame that belongs to another task > follows `current` when the window has no address, and only then" and "… > does not follow `current` when the window is on a task of its own", with nothing unaccounted for. Five isolated review rounds on a read-only worktree preceded acceptance. The accepted state is the integration gate on `e3224ca` — `gates 7, green 6`, `bun run test` and `bun run test:bun` each 39 files / 622 tests, `bun run test:ui` 95 passed.
