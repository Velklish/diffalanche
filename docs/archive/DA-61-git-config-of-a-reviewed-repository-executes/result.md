# DA-61 · Result

**Closed 2026-09-19.** Completed. A reviewed repository's own `.git/config` no longer names a program git runs. Three vectors were reproduced first, on the machine's git 2.54.0 (Apple Git-157) rather than the 2.39.5 of the card: `core.fsmonitor` and `diff.<driver>.textconv`, which the card had, and `filter.<driver>.clean`, which it did not — the last one executes on a plain `git diff`, because git filters the working-tree side through it before comparing. The model is [ADR-012](../../adr/adr-012-git-trust-model.md): the tool names the configuration and the repository names none of it. Every git process now carries `--no-pager` and the `-c` pins of `INERT_CONFIG` in `src/core/git/run.ts`, one per program-naming key the module can spell literally; `git diff` also carries `--no-textconv` beside the `--no-ext-diff` it already had. The keys whose *name* the repository chooses cannot be pinned literally and `git diff` has no blanket switch for them, so `repositoryDrivers` reads them out of the repository with `config --list --name-only -z`, filtered to the diff, filter and merge driver keys — `filter.<name>.required` among them, because git-lfs sets it and under it an emptied filter is fatal rather than skipped — and pins each to nothing. A repository whose configuration cannot be read is read no further: it comes back with `base: null`, no files and the warning `repository configuration could not be read`, and no `diff` is started in it, because degrading to "no pins" would make a git that cannot answer the cheapest way to switch the model off. That call joins the `Promise.all` that already resolves the base, so the cost is one more process per repository read — four to five — and no extra sequential step. The ADR carries the class key by key with "reached by the reader's commands" and "covered by" for each, `alias.*` and the `EDITOR`/`PAGER`/`VISUAL`/`SSH_ASKPASS` family included.

**Verification.** `tests/git.test.ts` builds a repository carrying four program-naming keys plus a tracked `.gitattributes` and `filter.pwn.required`, reads it, and asserts none of the four programs left its marker; a second verdict covers the refusal, with a `git` first on `PATH` that fails `config --list` and logs any `diff`, so the assertion is the warning **and** an empty log.
