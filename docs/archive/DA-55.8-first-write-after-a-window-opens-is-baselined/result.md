# DA-55.8 · Result

**Closed 2026-09-24.** Completed, with DA-60.3 merged into it. The first write after a window opens on a task — a comment, a base or a scope from a terminal — is a frame on that window: the baseline of a task a window has just opened is the document that window was served. `ReviewService.payload()` hands each document it serves to the watcher (`watcher.served(name, review, comments)`), and the watcher keeps it per task apart from the per-burst snapshots, so the burst between the document and the stream, which drops what nobody follows, leaves it. The burst that starts following the task compares its read of the files with that document: a write since is a `comment-added` or `session-changed`, what the document already had is not, nor a comment outside the document's scope. A served entry goes once a burst follows the task, when the task leaves the followed set, when the listing no longer has the task, and when the last window on the task goes (`createEventStream(capacity, left)` → `watcher.left`). It is looked up after the burst's read, so a write after a window's document is never lost; the price is a frame the window already has, or a comment deleted in that moment announced once and found gone. A stream that reconnects with no document served since is baselined in silence, as before. The card's two `src/core/watcher/index.ts` quotes guarded exactly the branches this changed, so they became `quote:before:` snapshots at this acceptance.

**Decisions this acceptance records**, taken by the orchestrator of run 0923 during the night. When two windows are served one task, the oldest document is kept: a frame seen twice is visible and idempotent, a loss is silent (PRODUCT.md, principle 5). What was served is looked up after the burst's read: a ghost the next burst corrects is taken over a silent loss. The orchestrator's first answer on the order — the lookup before the read, `a6720be` — traded a ghost for a silent loss; the worker showed it, and the orchestrator reversed it at 04:22:18Z (`9e8c0af`). The complete closure, a stream that knows its document, is [DA-55.11](../../backlog/minor/DA-55.11-stream-knows-its-served-document.md), not this card's. Three corners stay open, written in [05-watcher.md](../../reference/05-watcher.md#events) and carried by DA-55.11: a document whose window closed before its stream opened; a stream whose end reaches the server after the next document (a late reload teardown); a task another window already follows ([DA-55.10](../../backlog/minor/DA-55.10-followed-task-frame-between-document-and-stream.md)).
