# DA-55.3 · Result

**Closed 2026-09-22.** Completed. A named task's document is built from the working tree, not from a cache nothing refreshes. The card's option (a), with its staleness criterion replaced: the card proposed mtimes, and mtimes are a guess about the tree that costs a walk. The criterion taken instead is **who has been keeping the session fresh** — the watcher rewrites `diff.json` for the session it follows and for no other, so that one session's cache is trusted and every other session's change set is read from the working tree, bounded by the task's scope, and written back so that anchor capture reads a file saying what the screen says. `other()` became `changeSet()` in `src/server/review.ts`, which is where the rule lives. Option (c) — "say so on screen" — is rejected as the card instructs, because one of the other two was taken.

**Why this is not DA-55.1 and cannot be replaced by it.** The two cards invite the confusion, so the distinction is recorded: DA-55.1 keeps a document fresh **after** it is built. An agent prints `?review=X`, edits code, and the person opens the link — the watcher starts following X at that request at the earliest, so the document built for that very request still comes from the stale cache. DA-55.1 alone leaves the first view wrong. The build must be fresh; DA-55.1 then keeps it fresh.
