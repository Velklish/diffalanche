# DA-55.7 · Result

**Closed 2026-09-24.** Completed: a held document of a task nobody follows no longer keeps out what a terminal wrote to it. Reproduced first, on the base's code: `tests/server.test.ts` › "a held document of a task nobody follows" — a CLI comment (`expected [] to include 'c_jair52'`) and a CLI scope (`expected null to deeply equal [ { …(2) } ]`) written into a task with no window were missing from the next document served, and both narrower corners of the card reddened their own new tests. The fix is the card's first form: every change the watcher sees in the data directory (`onDataChanged`, said on the change itself, before the debounce, reading nothing) marks every held document (`dataChanged`), and the next read of a marked document reads its task's `review.json` and comments again — a re-read is `readReview` plus `list`, which reads `review.json` a second time for the scope, so a scope written between the two is caught by the next read. A moved base or scope builds the document again; anything else is patched in; a read that finds the same bytes keeps the held document and its serialisation. The price, measured by the worker on Bun on the synthetic review (200 comments, a 2.2 MB document, load 18–20, 41 reads, two runs): 1.2 and 1.3 ms for the first read after a burst against 0.22 and 0.24 ms for a held document. The live update's own fetch for a repository of `current` (`repository()`) reads no files: every rescan's session lock is itself a burst of the data directory. Followed tasks are marked too, because the watcher baselines a task it has just started following without a word. **Rejected:** the card's second form, a re-read on a move of `current` and when a stream opens — a window takes its document before the stream sends anything, so the read would land after the document it should have fixed. **Corner 1:** the first rescan of each repository after `current` moves reports `onRepositoryChanged` whatever it finds, once per repository per move, so a revert the move's read took in drops other tasks' documents of the edit it undid. **Corner 2:** a build resolves as followed when `followed || watched() === session`, so a build started during a move keeps a rescan that landed after it. Closed with them: a re-read no longer undoes a rescan that landed while the files were read (it patches `entry.document`, not the copy it started from), a re-read asked earlier that lands later keeps the later one, and the walk's takeover of the data directory's watch marks too (tested). **Left open:** the window between a write and its notification — a `?review=` opened inside it is served the older document until the next burst.
