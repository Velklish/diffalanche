# DA-55.1 · Result

**Closed 2026-09-22.** Completed. The watcher follows every task a window is open on, so a window on `?review=X` hears about X's comments instead of learning of them at the next reload. Before this, `reloadComments` and `reloadMetadata` read whatever `readCurrent` last returned, which was invisible until DA-55 gave a window a task of its own and decision 7 of ADR-010 made a window on a task that is not `current` the normal case.

**This commit also carries the emitter half of a frame split, and the apportioning rule is recorded because the split spans two tasks.** A critical regression found in the fourth review round — an address-less window that stopped following `current` while it kept *writing* to `current`, so a comment from the screen showing A would land in B with an anchor from A — was fixed by splitting one frame in two: `current-changed` for "the pointer moved", `session-changed` for "a followed task's metadata changed". The two halves were apportioned by **which side of the wire each is on**. The emitter is the watcher, and it is here: `src/core/watcher/bus.ts` gains the `current-changed` member, `src/core/watcher/index.ts` emits it from `reloadCurrent`, `src/server/serve.ts` gains the explicit branch that drops nothing on it, and `tests/watcher.test.ts` asserts both directions. The reader is the page and is [DA-68](../DA-68-session-identity-is-not-carried/result.md), because it is DA-68's rule that needed the exception. The two-line revert was refused for a reason worth keeping: after this task every followed session emits that frame, so passing it through for the address-less window would re-read the review on any watched session's change, which is what ADR-010 forbids.

**The test consequence is the check on that reasoning.** After the split, six waits in `tests/watcher.test.ts` that expected `session-changed` on a pointer move went red — two on the assertion and four as a cascade, the first test throwing before restoring the pointer and the rest then waiting 20–40 s for metadata of a session no longer followed. Those six are renamed in this commit, which is where the emitter changed. **The old behaviour was covered, and at the watcher**: the fourth-round note that there were no tests for either behaviour is true of the client and false of the watcher — `tests/watcher.test.ts` asserted the frame, and it is what caught the rename. A strengthening went in with the fix, `expect(since(mark, "session-changed")).toEqual([])` on a pointer move, so the suite now asserts what the split *distinguishes* and not merely what it emits.

**Verification.** Five isolated review rounds on a read-only worktree and the track's gate rounds; the accepted state is the integration gate on `e3224ca` — `gates 7, green 6`, `bun run test` and `bun run test:bun` each 39 files / 622 tests, `bun run test:ui` 95 passed, the single red being a perf line red on the base with a worse number. The full record, the rebase and the conflict resolutions are in [DA-24.1's result](../DA-24.1-session-switch-cold-path/result.md). This commit is `b86362b` there, and it is the one whose `patch-id` differs **without** a conflict having been raised on it: comparing only its `+`/`−` lines against `83abb7b` shows them byte-identical, `git diff --numstat` reports `23 7` on `CHANGELOG.md` on both sides, and what moved is one context line — the entry following this one changed from DA-55.4's to DA-76.1's, which `main` put there.
