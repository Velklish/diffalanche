# DA-79 · Result

**Closed 2026-09-19.** Completed. Both writers of `warnings` go through one named rule, `afterWarnings` in `src/ui/store.ts`: a list that says something new clears `warningsDismissedFor` and the remembered dismiss in `sessionStorage` alike, an identical list changes nothing. `setWarnings` is that call and nothing else; `fromDocument` takes the list the page holds as a fourth argument instead of writing `warnings: document.warnings` flat past the comparison. **The card's open question — what "something new" means across a session switch — took two goes to answer, and both wrong turns were caught by machines rather than by reading.** The comparison is between two reads of *the same session*: a read that switches sessions stores the warnings and leaves the dismissal to its key, which is what `fromDocument`'s existing `switched` already tells it. The first answer was "run the comparison always", on the argument that the per-session key does not match the new name anyway so the bar shows either way — true for the new session, and false for the way home: dismiss on `ls-1`, look at `ls-2`, come back, and `ls-2`'s list had already cleared the dismissal, so the bar returned where before DA-79 it had stayed away. The isolated review found it.
