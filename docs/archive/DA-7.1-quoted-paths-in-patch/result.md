# DA-7.1 · Result

**Closed 2026-09-05.** Completed. `src/core/git/patch.ts` takes file paths from the patch header instead of from the parser, which reads them literally while git does not write them literally: `---`/`+++` when present (tab padding stripped), `rename from`/`rename to` for a pure rename, the `diff --git` line split down the middle (both halves checked against each other) for a mode-only change or a binary file. Git's C-style quoting is undone byte for byte (`\a \b \f \n \r \t \v \" \\` and octal escapes, decoded as UTF-8 at the end), and the synthetic patch of an untracked file quotes its path with the inverse rule (control characters, `"`, `\`, DEL, bytes ≥ 0x80), so a name with a tab or a newline no longer cuts or tears the patch. `-c core.quotePath=false` was rejected: it removes the quoting of non-ASCII names and nothing else. The header is cut at the first hunk before it is split, so a large patch is not walked twice on the review path.
