# DA-6 · Result

**Closed 2026-09-05.** Completed. `src/core/scanner/` replaces the spike's `scan.ts`: `scan(root, config)` walks each entry of `roots` to `depth` levels, treats a directory holding `.git` as a repository and does not descend into it, reads a `.git` file's `gitdir:` pointer to tell a linked worktree (kind `worktree`, main working tree two levels above the `worktrees` segment) from a submodule pointer (kind `repo`), matches `exclude` globs against the directory name and the root-relative path (`**/` spans whole segments, a trailing `/` is dropped), never follows symbolic links, and reports warnings `{ path, message }`: "worktree of <repo>" when the main repository is also under the root (matched on resolved paths, because `git worktree add` writes an absolute, realpath-resolved `gitdir` while a typed root may run through a symlink), "directory cannot be read", and "root is itself a repository; it is not reviewed — put it under a subdirectory or set roots" (the root is neither listed nor walked into: SPEC §3 decision 3 says a found repository is never scanned inside, and the root is no exception — a follow-up `c54dff9` integrated with DA-7 after the DA-7 review caught the first version, which walked through the root). Repository ids are paths relative to the root including the `roots` prefix, as the fixture writes them; results are ordered by code point so both runtimes order the same root identically. Types `ScanConfig`, `Repository`, `RepositoryKind`, `ScanWarning`, `ScanResult` are additions to `src/core/types.ts`; `ReviewBundle` is unchanged.

Review by an isolated session: 1 major (`**` matched without a segment boundary, so `**/group` excluded `subgroup`), 5 minor (relative `gitdir` versus realpath keys, locale-dependent ordering, glossary row, status baseline taken after the first scan, the root itself reported with an empty id), 2 nits — all fixed in `071709d`.
