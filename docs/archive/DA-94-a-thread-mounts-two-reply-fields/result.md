# DA-94 · Result

**Closed 2026-09-19.** Completed. The first of the card's candidates: `replyId` names the thread and `replyAt` names the copy `Reply` was pressed on, so only that copy draws the field and only it takes the caret. The card takes a `place` prop — `widget` or `rail` — which is **deliberately not `scope`**: both copies of a thread on the file being read are `scope="file"`, so overloading it would put the same defect in another place. The field stays where the reader pressed `Reply`, which is the composer's own rule, and a thread with no widget — a comment on a whole file, or one whose line a collapsed hunk hides — is drawn in the rail alone and opens its field there. **What the review round added:** since the rail no longer draws the field the widget owns, the card holding it may not be unmounted from under the caret, so `FileCard`'s `busy` now covers a reply being written in one of its own widgets — the same rule ADR-008 already gave the composer and a drag.

**Verification.** Two cases in `e2e/threads.spec.ts`: `Reply` on the widget opens exactly one field, inside the widget, and the same from the rail; and a file-level thread, which has no widget at all, opens its field in the rail. The `.rail-list` prefix at `e2e/threads.spec.ts:198` is **kept deliberately and says why** — that case is about a reply written from the rail, and the same thread is drawn under its line as well. Mutation probe on `9e4cc01`, tree empty at both ends: the `replyAt` check removed so both copies draw again — exit 1, 9 of 10, the expected case red on the count. The Impeccable pass ran over the thread surface: the detector returns `[]`, and `design-contrast` + `design-tokens` are green at 62; it found nothing to fix here, because the change is which copy renders a control that already existed. **The `busy` fix shipped first with nothing guarding it** — removing it left the suite green — and the case written for it then scrolled a fixed 4000 px, which often left the card inside its 1000 px mount margin, so the probe stayed green a second time. It scrolls to the end of the document now and first asserts the card was mounted at all; the probe reddens it, 10 of 11.
