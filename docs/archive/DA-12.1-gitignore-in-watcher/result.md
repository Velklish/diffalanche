# DA-12.1 · Result

**Closed 2026-09-05.** Completed. Files git ignores no longer wake the watcher: before a rescan, `burstIsIgnored` asks `git check-ignore --stdin -z` once per repository per debounce window (`checkIgnore` in `src/core/git/run.ts`, NUL in and out, the same read-only config isolation as the untracked read, `stdin` and process errors caught, `null` when git could not answer — never cached, the caller does the work) and skips the rescan only when every path of the burst is ignored. Verdicts are cached per repository (at most 4096, oldest out, trimmed after the burst is answered), cleared when `.gitignore` at any level, `.git/info/exclude`, or `.git/index` changes (the index decides which files the rules apply to at all — after `git add -f` a path is tracked and in the diff). Any path under `.git` makes the whole burst pass: `check-ignore` makes no exception for `.git/HEAD` or `.git/index` (a `*` gitignore reports them ignored), and a commit or branch switch is a burst of exactly those files. The debounce ceiling and `sameChange` are unchanged; `.git/info/exclude` is watched. Measured once: about 20 ms for fifty paths in one process, next to a rescan of one repository at 90–100 ms. The domain types module became a pure-types leaf (`Base` imported from `storage/types.ts`) so the UI project can import `SessionSummary` without Node types.

Review by an isolated session: 4 major (`stdin` without an `error` listener; `.git` paths not exempt from suppression; the cache surviving index changes; a test that passed with the feature removed) and 5 minor (a test named for a check it did not make; leftover state between tests; wording; wrapping; failed verdicts cached) plus the cap missing from CHANGELOG — closed in `c4e322b` and `8ae917e`, where two of the new tests were rewritten after their probes stayed green (the `.git/index` burst passed through the exemption; the `.git` test's rule hid nothing).
