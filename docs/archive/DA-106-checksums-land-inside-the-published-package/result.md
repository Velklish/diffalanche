# DA-106 · Result

**Closed 2026-09-21.** Completed. The release workflow's checksums step wrote `SHA256SUMS.txt` into `dist/`, and the same job publishes to npm from that tree with no rebuild in between; `files` in `package.json` excludes the platform binaries but not the manifest, so every published tarball carried a six-line list of binaries it does not contain. The manifest now goes to `$RUNNER_TEMP` and the release uploads it from there under the same name. Of the three candidates this is the one that makes the invariant **structural** rather than a second exclusion somebody has to keep in sync: `dist/` stays exactly what the npm channel ships. Both checks the step exists for are unchanged — the six-line count and the `sha256sum -c` re-read from inside `dist/`. A guard was added beside the fix so the invariant is asserted rather than remembered: `scripts/check-package.ts`, exposed as `bun run check:package`, runs `npm pack --dry-run --json` and refuses anything under `dist/` that is not `dist/cli.js` or under `dist/ui/`. It runs in the `check` job of CI, so a stray file stops a merge rather than a tag.

**Verification.** Driven in both directions on the branch. `bun run check:package` on the tree as it ships: `check:package: 17 files, nothing unexpected out of dist/`, exit 0 — and seventeen is the same count DA-31.1 recorded before the checksums step existed, which is the point. With a manifest planted back where the bug used to put it (`echo "abc  diffalanche-linux-x64" > dist/SHA256SUMS.txt`): `check:package: the tarball carries 1 unexpected entry out of dist/: dist/SHA256SUMS.txt`, exit 1. Mutation probe 4 of the track, on `a009129`: `scripts/check-package.ts:28` made `unexpected()` stop looking inside `dist/`, run exit 1, reddening `names the checksums manifest, the binaries, and anything else left in dist/`; `git status --porcelain` empty at both ends. The verdicts live in `tests/package.test.ts`.
