**Closed 2026-09-18.** Completed. Every read in `src/core/storage/index.ts` translates the errno codes it can name and rethrows the rest; the two `mkdir` calls translated none. So a read-only mount, a full filesystem or a `--data-dir` owned by someone else reached the person as `EACCES: permission denied, mkdir '…'` with a stack trace and exit 2 — against the module's own rule and against `03-storage.md`'s "everything storage refuses is a `StorageError` carrying `file` and `field`". `ensureDataDir` and `ensureSessionDir` now create their directory through one helper, `makeDir`, which words `EACCES` and `EPERM` as "permission denied", plus `EROFS`, `ENOSPC`, `ENOTDIR` and `EEXIST` — a recursive `mkdir` passes over a directory that is already there and refuses a file at the same path with that last one — and names the directory the errno itself carried: `diffalanche: /srv/shared/.diffalanche: could not be created: permission denied`. The scope of the wrapping is those two `mkdir` calls and nothing else: the wider candidates, every write in storage or a translation the whole module's write path goes through, would have meant re-reading the lock protocol's own errno handling, which distinguishes codes deliberately, and that is a bigger decision than this entry carries. An errno the helper does not word is rethrown untouched and keeps exit 2.
