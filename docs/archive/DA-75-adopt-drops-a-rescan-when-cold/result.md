# DA-75 · Result

**Closed 2026-09-22.** Completed. A rescan announced before it reached disk is kept rather than dropped. `ReviewService.adopt` used to be a silent no-op whenever no document was held, so the watcher's `diff-changed` — sent before `writeDiffCache` on purpose, to spare the latency the update budget of `docs/SPEC.md` section 6 measures — was thrown away and the next build read a `diff.json` that had not been written yet. Candidates (iii) + (ii) of the card were taken; candidate (i), announcing after the write, is rejected because it spends exactly the latency that comment exists to avoid.

What landed: `adopt(session, cache)` records the change set on the session **whether or not a document is held** and returns whether a held document took it, so the caller can tell the two cases apart; `build()` prefers that recorded change set over `diff.json`; the in-flight half is covered by re-checking the recorded cache **after** the build resolves (`withAdopted`) and not only at its start, so a build that read the pre-edit file and resolves after the rescan is reconciled on its way out instead of being installed; `invalidate` drops the document and its bytes and **leaves the recorded change set alone**, because a write to the data directory is not a change of the working tree; and the `warnings` event no longer forces a re-read — it rides on the rescan the document already has.
