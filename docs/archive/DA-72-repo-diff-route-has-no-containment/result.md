# DA-72 · Result

**Closed 2026-09-18.** Completed. `GET /api/repos/:repo/diff?review=<name>` took the repository from the URL and carried it to a `join` against the root with nothing on the way asking whether the result was still under it. Hono decodes the segment before routing, so a literal `../` was normalised away while `%2e%2e%2f` and `..%2F` arrived intact, and the only gate on that path was the scope — which is `true` for every string on a session created without one. `freshRepository` now resolves the path against the root and refuses it when it does not stay below, before any git process starts. The check is a path check and not a walk, deliberately: the route is on the live path — the stream calls it on every event — and `findRepositories(config)` is a filesystem walk of the root per request. What a path check lets through is a path inside the root that is not a repository, and the route already answers that: no base resolves, no files come back, 404. The refusal is that same `404` `error: "no-such-repository"` rather than a code of its own — from outside, a path that leaves the root and a path the change set does not have are the same answer, and telling them apart would say which encodings got through. The other consumer of a client-supplied repository path, `POST /api/comments`, already checks against `findRepositories(config)`, is not on the live path, and is left as it is.
