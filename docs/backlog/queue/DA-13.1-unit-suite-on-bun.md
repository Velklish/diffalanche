# DA-13.1 · The unit suite never runs on Bun's own runtime

- **Order:** 185
- **Scope:** 11-perf, 06-cli (see [reference](../../reference/README.md))
- **Created:** 2026-09-05
- **Dependencies:** DA-15

## Context

Finding from DA-13/DA-14 (worker cli). `bun run test` starts Vitest through Bun, but Vitest 5 spawns its workers with Node: inside a test `process.execPath` is the Node binary and `globalThis.Bun` is `undefined`. Evidence: a throwaway test writing `process.execPath` and `process.versions` to a file (Vitest swallows `console.log` in the default reporter); `tests/cli-comments.test.ts` "two processes" spawns the CLI from source with `process.execPath` and gets Node 25.2.1 on the development machine.

Two consequences:

- SPEC section 10 asks for "green on Node and Bun"; `.github/workflows/ci.yml` runs `bun run test` once, which is the Node side only. Nothing runs the unit suite on Bun's runtime. DA-15 adds the smoke matrix (`node`, `bun`, `binary`) for the CLI, not the unit suite.
- Tests that spawn the CLI from source rely on Node stripping TypeScript types by default, which it does since 22.18; `package.json` declares `engines.node >= 22`, so a developer on 22.6–22.17 gets an opaque failure in those tests (the published `dist/cli.js` is plain JavaScript and unaffected).

## Work to do

- Decide whether the unit suite runs on Bun as well (for example `bun test` over the Vitest suite is not the same runner; a second CI job running Vitest with `--pool` on Bun, or a Bun-native subset for the runtime-sensitive modules — storage lock, git reader, watcher) and record the decision in `docs/reference/11-perf.md` next to the matrix.
- Raise `engines.node` to `>= 22.18` or add `--experimental-strip-types` guidance to README for the tests that spawn the CLI from source.

## Out of scope

- The smoke matrix itself (DA-15) and the release matrix (DA-31).

## Verification

- CI prints which runtime executed the unit suite, and the documentation says the same.
- `bun run test` on Node 22.18 passes; the README names the minimum for running tests from source.
