# DA-88.1 · The test that guards "a refusal rewrites nothing" compares bytes, and a rewrite puts the same bytes back

- **Order:** 252
- **Scope:** 06-cli (see [reference](../../reference/README.md))
- **Created:** 2026-09-18
- **Dependencies:** none

## Context

[tests/cli-comments.test.ts:144-165](../../../tests/cli-comments.test.ts), "refuses a `--repo` no
repository is at, before it writes anything", reads `diff.json` before the failing command and
asserts the string is identical after:

```ts
    const before = readFileSync(join(root, ".diffalanche", "reviews", "alpha", "diff.json"), "utf8");
    …
    expect(readFileSync(join(root, ".diffalanche", "reviews", "alpha", "diff.json"), "utf8")).toBe(before);
```

A rewrite of that cache by `refreshRepository` writes the *same bytes* when the repository has not
changed since the last scan, which is exactly the state a test fixture is in. So the assertion holds
whether the refusal rescanned or not, and the invariant the test is named after is not covered by it.

Measured, not argued. While closing DA-88 the same byte comparison was written for the anchor-level
refusals and the mutation probe came back green: with the new guard removed — `assertAnchorLevels`
replaced by `void assertAnchorLevels;` in `src/cli/commands/comment.ts` — `bunx vitest run
tests/cli-comments.test.ts` exited **0**, 17/17, although the refusal did rescan and rewrite. The
same test rewritten to stamp the cache's mtime back to 2020 and assert it afterwards turned the
probe red on the same mutation: `expected 1789761067271.2395 to be 1577836800000`, exit 1, 16/17.
The mtime is what the DA-88 entry itself reproduced with.

The case this entry is about is the `--repo` one, which still has only the byte comparison. Its
check does run before the refresh today, so the test is not wrong about the current code — it simply
cannot fail if that ever changes, which is the whole reason it exists.

## Work to do

- Give the `--repo` case the same evidence the anchor-level case now has: stamp `diff.json`'s mtime
  back before the command and assert it afterwards, keeping the byte comparison beside it.
- Look for the same shape elsewhere in the suite: a "nothing was written" assertion that compares
  content a rewrite would reproduce. `grep -rn "toBe(before)" tests/` is the starting point.
- Decide whether the invariant deserves a shared helper — "this file was not written" is asserted in
  more than one place and the correct way to assert it is not obvious.

## Out of scope

- The anchor-level refusals themselves, closed in DA-88 with the mtime assertion.
- Making `refreshRepository` skip a write when the content is unchanged. That would make the byte
  comparison meaningful by changing the product to suit a test, and it is a separate decision with
  its own cost — the watcher's behaviour depends on when that file is written.
