`chmodSync(…, 0o000)` and skip themselves as root, so in a cloud session, which runs as root,
they check nothing:

- `tests/scanner.test.ts` › "warns about a directory it cannot read" (`it.skipIf(process.getuid?.() === 0)`);
- `tests/embedding-index.test.ts`, the case at the second `chmodSync` (`it.skipIf(process.getuid?.() === 0)`);
- `tests/delivery.test.ts`, the case skipped on `win32` or root.

DA-117.1 made a listing fail for root by putting a file where the directory was (`ENOTDIR`).
Assumption, not checked: the same would stage at least the scanner's case, unless its warning
is tied to `EACCES`; the other two have not been read for it.
