# DA-33.2 · The one-second budget for 200 comments was never measured on a quiet machine

- **Order:** 770
- **Scope:** 09-ml, 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-23
- **Cost:** major
- **Dependencies:** none

## Context

Finding discovered while accepting DA-33. DA-33's verification asks that 200
comments embed in under a second after warm-up, and no run met it: every run
shared the machine with other agents. The owner accepted
[ADR-014](../../adr/adr-014-embedding-model-and-npm-delivery.md) as proposed on
2026-09-23 without this number, on the condition that it is measured here and
that a miss goes back to the owner. ADR-014 records the gap:

<!-- quote:../../adr/adr-014-embedding-model-and-npm-delivery.md -->
- **Not yet measured on a quiet machine: the one-second budget.** The best wall
  time for 200 comments was 1.86 s on Node and 1.94 s on Bun, the module as
  committed at load averages of 21–28; one thread spent 2.0 s of CPU on them. Whether four to six quiet cores bring that under a
  second is unmeasured. The owner accepted this without it: DA-33.2 measures it,
  and a miss returns the budget to the owner.
<!-- /quote -->

Evidence: the worker's measurement matrix of 2026-09-23 (`evidence-ml.md` of
run 0923, table "The module as committed"): the best wall time for 200 comments
was 1.86 s on Node at a load average of 21.0 and 1.94 s on Bun at 28.0, with
2.5–2.9 s of CPU per 200 comments across the 22 runs of that table. No run was
taken on a quiet machine, so whether four to six idle cores bring the wall time
under a second is not known.

## Work to do

- Embed 200 comments of the synthetic corpus after warm-up with the module as
  committed, with intra-op threads 1, 4 and 6 and spinning off, five runs each,
  on a quiet machine and under `/tmp/da-perf.lock`; record the load average
  beside every run.
- If at least one setting has a median wall time under one second, make that
  thread count the module's and record the numbers in
  [09-ml](../../reference/09-ml.md) and [11-perf](../../reference/11-perf.md).
- If none does, take the numbers to the owner: the budget goes back to them,
  and ADR-014 names 2B as the alternative whose budget would be restated.

## Out of scope

- The choice of model and runtime (ADR-014).
- The event loop of the server during a run (DA-34.1).

## Verification

- Five runs per setting with wall time, CPU time and load average each, and a
  median under one second for the chosen setting — or the owner's decision on
  the budget, as a new ADR superseding ADR-014 if it changes the decision.
