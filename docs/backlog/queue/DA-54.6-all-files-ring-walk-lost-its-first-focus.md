# DA-54.6 · The ring walk of all files lost the focus of its first row once in three gates chains

- **Order:** 780
- **Scope:** [08-ui](../../reference/08-ui.md)
- **Created:** 2026-09-24
- **Cost:** major
- **Dependencies:** none
- **Parent:** DA-54.4

## Context

Finding discovered while working on DA-54.4, in the three `backslop gates --keep-going
--require-clean` chains worker:perf1 of run 0923 ran back to back on `fa471a4` under
`/tmp/da-perf.lock` (05:46–05:59 UTC, 2026-09-24, an 8-core M1 Pro). Chains 1 and 2
were `gates 7, green 7`; chain 3 was `gates 7, green 6` on one spec of `bun run test:ui`,
150 passed and 1 failed:

```
e2e/focus.spec.ts:294:3 › every stop of all files and browse mode draws the system's ring (light)

Error: expect(locator).toBeFocused() failed
Locator:  locator('.file-row.unchanged').first()
Expected: focused
Received: inactive
Timeout:  5000ms
  14 × locator resolved to <button type="button" class="file-row unchanged">…</button>
     - unexpected value "inactive"
  at focusByKey (e2e/focus.spec.ts:139:48)
  at e2e/focus.spec.ts:300:5
```

The step is the first `focusByKey` after `all files` is pressed and the first unchanged row
has appeared:

<!-- quote:../../../e2e/focus.spec.ts -->
async function focusByKey(page: Page, selector: string): Promise<void> {
  await page.keyboard.press("F2");
  await page.locator(selector).first().focus();
  await expect(page.locator(selector).first()).toBeFocused();
}
<!-- /quote -->

The suite had started after its load precondition waited 35 s — `quiet after 35 s: load
averages 19.87 and 15.27 … 2.48 and 1.91 per core` — so it ran at the ceiling.

It did not come back. The spec alone twice on `fa471a4` and twice on the base `f9cda1b`,
one-minute averages 5.3–5.9: exit 0 all four. Then twelve runs alone, the base and the
branch in turn (A G G A …), while `bun run test:bun` ran four times beside them in another
worktree, one-minute averages 13.8–50.5: exit 0 all twelve, six a side. The code the spec
drives is the base's — `git diff f9cda1b fa471a4 -- src/ e2e/focus.spec.ts` is empty — and
the base's own chain of the same morning passed all 151.

So it is a red nobody can reproduce yet, on code both trees share. Assumption, not measured:
the row that took the focus was replaced under it — the `all files` listing, or a live
patch of the tree, re-rendering the row after `focus()` — which a busy machine makes more
likely and does not cause.

## Work to do

- Find what takes the focus away from the first unchanged row between `focus()` and the
  assertion: read `document.activeElement` and the row's identity across that interval in
  a loop of the spec under load, until it goes red once with the trace on.
- If the row is remounted, decide whether that is the page's defect — a focused row
  should survive a re-render of its list — or the spec's, which then has to wait for the
  listing to settle before it walks.

## Out of scope

- The load precondition of the UI suite, which is DA-54.4's and did what it says.
- Making the other live specs tolerant of a slow machine (DA-54.4, "Out of scope").
