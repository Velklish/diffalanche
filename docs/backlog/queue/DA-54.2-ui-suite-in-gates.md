# DA-54.2 · The Playwright UI suite is in no gate: test:ui is manual and CI runs only acceptance

- **Order:** 290
- **Scope:** 08-ui, 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-10
- **Dependencies:** none

## Context

Found during the review of DA-54, whose entire verification is a new Playwright spec — and that spec runs in no gate at all.

Where the suite is not:

- `gates` in [backslop.json](../../../backslop.json) holds `backslop lint`, `bun run lint`, `bun run typecheck`, `bun run test`, `bun run test:bun` and `bun run perf`. Neither `test:ui` nor `test:e2e` is among them.
- `bun run test:ui` appears nowhere in [.github/workflows/ci.yml](../../../.github/workflows/ci.yml). The chromium install at line 88 belongs to the `perf` job.
- The one Playwright run in CI is `bun run test:e2e` at line 170, and its config [e2e/acceptance.config.ts](../../../e2e/acceptance.config.ts) sets `testMatch: /acceptance\.spec\.ts$/` — only the acceptance spec.

So the suite of [e2e/playwright.config.ts](../../../e2e/playwright.config.ts) — ten spec files, 65 tests covering the sidebar, the thread rail, live update and now the repository bar — runs only when a person types `bun run test:ui` by hand. A UI regression reaches the main branch through six green gates and a green CI.

The gap is older than DA-54; the task only made it visible, because there a spec file *was* the deliverable and "the gates are green" said nothing about it.

The two suites already know about each other: the comment at `acceptance.config.ts:14` says a build there pulls the page out from under a `test:ui` in flight. So they cannot simply be run side by side, and that is the substance of this task rather than a detail of it.

## Work to do

- Decide where the `playwright.config.ts` suite runs and put it there — a `gates` entry, a CI job, or both. A CI job is the weaker of the two on its own: a gate is what a worker runs before reporting, and the suite is cheap enough to be one (65 tests, 37 s measured on 2026-09-10).
- Whatever is chosen has to hold against the collision the two configs already document: a build under one suite invalidates the page under the other. Separate jobs, separate ports, or a build shared by both — the choice is the decision this task records.
- If the suite becomes a gate, [DA-54.1](../active/DA-54.1-e2e-fixture-ignores-user-config.md) has to land first or together: today `test:ui` does not start at all on a machine whose user config sets a relative `dataDir`, so making it a gate before that fix turns a manual annoyance into a red gate for that developer.

## Out of scope

- Fixing the fixture's inheritance of the user config — that is DA-54.1.
- Adding Playwright coverage. This is about running what already exists.

## Verification

- A change that breaks one of the ten spec files of `playwright.config.ts` is caught without anybody typing `test:ui` — shown by breaking one on purpose and watching the chosen gate or job go red.
- `bun run test:e2e` and the UI suite do not pull the page out from under each other when both run in the same CI run: shown by running them as CI runs them, twice.
