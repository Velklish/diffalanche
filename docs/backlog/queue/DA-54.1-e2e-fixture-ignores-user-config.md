# DA-54.1 · The e2e and perf fixtures inherit the developer's user config and cannot find their data

- **Order:** 280
- **Scope:** 03-storage, 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-10
- **Dependencies:** none

## Context

Found while working on DA-54, on a machine whose `~/.config/diffalanche/config.json` holds `{ "dataDir": ".agents/diffalanche" }`. On such a machine `bun run test:ui` and `bun run test:e2e` never start: Playwright gives up with `Error: Timed out waiting 120000ms from config.webServer` after two minutes.

The server is up the whole time — it is answering, just not about the fixture:

- `curl http://127.0.0.1:4881/` → 200,
- `curl http://127.0.0.1:4881/api/review` → 404, `{"error":"no-current-session","message":"no current review session: create one with `review new` or name one with --review"}`,
- the same server started with `DIFFALANCHE_DATA_DIR=.diffalanche` → 200.

The cause is the DA-52 decision working as designed on data it was not meant to see. `resolveDataDir` ([src/core/config/index.ts:141](../../../src/core/config/index.ts)) resolves `user.dataDir` against the **root**, so for the fixture root `.perf/e2e` it looks in `.perf/e2e/.agents/diffalanche`. The synthetic review writes its session to `.perf/e2e/.diffalanche/` (`config.json`, `current` holding `synth`, `reviews/synth/`), and the two never meet.

Relative-to-root is the right behaviour for a real root: a person who writes `.agents/diffalanche` in their user config wants their review data beside the code. The defect is that a **test fixture is not isolated from that config at all** — a personal file outside the repository decides whether the repository's own gates pass. Whoever has no `dataDir` in their user config sees green; whoever has one sees a two-minute timeout with no explanation pointing at the cause.

`bun run perf` is likely to be affected the same way and was not measured — it stands on the same fixture and the same server.

A second, independent symptom of the same cause turned up in DA-53, through the CLI rather than the fixture harness: taking the live output of `review` commands for the shipped skills, the command looked for its data outside the fixture and had to be run with an explicit `--data-dir .diffalanche`. Two different entry points, two different workarounds (`DIFFALANCHE_DATA_DIR` and `--data-dir`), one cause.

## Work to do

The repository already solves this, in one place out of three. [vitest.config.ts](../../../vitest.config.ts) neutralises the developer's environment for the unit suite, and its own comment names this exact problem: the data directory can come from the developer's environment and `~/.config/diffalanche/config.json`, and a test run must not. It does it with two lines — `DIFFALANCHE_DATA_DIR: ""` and an `XDG_CONFIG_HOME` pointing at a directory nothing writes to.

The other two harnesses never got those lines:

- [e2e/playwright.config.ts](../../../e2e/playwright.config.ts) — the `webServer` block carries `command`, `cwd`, `url`, `reuseExistingServer` and `timeout`, and no `env` at all. Playwright's `webServer` takes an `env`; give it the same pair.
- [perf/gate.ts](../../../perf/gate.ts) — the same gap, and it spawns its own server per repetition.

Both fixes are the two lines that already exist, moved to a shared place rather than copied a third time.

The silence is worth fixing with them. `webServer.url` is `/api/review` — the very route that answers 404 when the data directory resolved elsewhere — so Playwright polls a route that will never turn 200, and after two minutes reports `Timed out waiting 120000ms from config.webServer`. The message names the symptom and hides the cause. Either the readiness probe points at a route that is up regardless of the session (`/` already answers 200), or the fixture server says on startup which data directory it resolved and that it holds no session.

## Out of scope

- Changing the DA-52 decision. Resolving `user.dataDir` against the root is deliberate and correct for a real root; this entry is about test fixtures inheriting it.

## Verification

- With `{ "dataDir": ".agents/diffalanche" }` in `~/.config/diffalanche/config.json`, `bun run test:ui` and `bun run test:e2e` are green without any environment variable on the command line.
- With no `~/.config/diffalanche/config.json` at all, both stay green.
- `bun run perf` is measured under both configurations and is green under both.
