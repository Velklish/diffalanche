# DA-55.8 · The first write after a window opens on a task reaches it as no frame

- **Order:** 800
- **Scope:** 05-watcher, 07-server (see [reference](../../reference/README.md))
- **Created:** 2026-09-24
- **Dependencies:** none
- **Parent:** DA-55.7
- **Cost:** major

## Context

Found while working on DA-55.7. A window opened on a task by `?review=` registers
the task through its stream, and the watcher follows it from the next burst of
the data directory on. That burst takes the task's comments as a baseline without
announcing anything:

<!-- quote:../../../src/core/watcher/index.ts -->
```ts
    // Nothing was read the last time — a file being written as it was read, one
    // broken by hand and since repaired, or a task a window has just opened.
    // What is in it now is the baseline, not two hundred comments that were all
    // just added.
    if (before === undefined || before === null) {
      comments.set(name, snapshotOf(list));
      return;
    }
```
<!-- /quote -->

When the first burst after the window opened is the write itself — an agent's
`review comment` into the task it just printed a link to, with nothing else
written in the data directory in between — that write is the baseline, and no
`comment-added` goes out. The window shows the comment only after a reload. The
second write is heard.

Reproduced on the DA-55.7 branch (after its fix, which does not touch this) with a
scratch test in `tests/server.test.ts`, not committed: a server on its own data
directory, a stream on `current` armed with a created task, `GET
/api/review?review=named-task`, a stream on `GET /api/events?review=named-task`
waited open (its first bytes read), then `addComment` into `named-task`, a
barrier task, a second `addComment`, a second barrier. The window's stream
carried the second comment's id and not the first's: `first=false second=true`,
`npx vitest run tests/server.test.ts -t "SCRATCH"` exit 0 on 2026-09-24.

**The metadata has the same shape.** Found by the review of DA-55.7 and read
from the code, **not reproduced**. The watcher drops the metadata of every task
it does not follow on each burst, and a task it has just started following has
none, so its first read is taken as the baseline and announces nothing:

<!-- quote:../../../src/core/watcher/index.ts -->
```ts
      const known = metadata.has(name);
      metadata.set(name, next);
      // A task a window has just opened is not a task that changed: its
      // metadata is read as the baseline, the way its comments are.
      if (!known) continue;
```
<!-- /quote -->

So a `review base --review X` or `review scope --review X` that is the first burst
after a window opened on `?review=X` sends no `session-changed`, and the window
shows the old base or scope until it reloads.

The held document is not affected since DA-55.7: the same burst marks it, and
the next read of it carries the comment, the base and the scope. What is lost is
the live frame.

## Work to do

- Keep the repro as a test: a comment written right after a window opened on a
  task, with no burst in between, reaches that window's stream.
- A second test for the metadata: a `review.json` written right after a window
  opened on a task — a base or a scope set from a terminal — reaches that
  window as `session-changed`.
- Decide where the baseline comes from, **for the comments and the metadata
  alike**: one decision, since both are snapshotted by the same first burst.
  Taking it when the stream opens narrows the gap but leaves the moment between
  the window's document and its stream; a baseline no newer than what the window
  was served closes it, and the watcher drops the snapshot of a task nobody
  follows on each burst, which that shape has to survive.

## Out of scope

- The held document of such a task, which DA-55.7 keeps honest.
