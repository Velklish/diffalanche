# DA-45.1 · Every git process pins its configuration to os.devNull, which Git for Windows cannot open

- **Order:** 355
- **Scope:** [02-git](../../reference/02-git.md)
- **Created:** 2026-09-29
- **Dependencies:** none
- **Parent:** DA-45
- **Cost:** major

## Context

Finding discovered while working on DA-45. Every run of `smoke node on windows-latest` stops in `scripts/synth.ts` at its first `git init`, for example Velklish/diffalanche#7, job 109224920874:

```
fatal: unable to access '//./nul': Invalid argument
synth: Command failed: git -C C:\Users\RUNNER~1\…\sources\vendor-lib -c init.defaultBranch=main … init -q
```

`scripts/synth.ts` sets `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` to Node's `os.devNull`, which is `\\.\nul` on Windows, and git cannot read a configuration file at that path. `readOnlyEnv` in `src/core/git/run.ts` does the same for every git process the product starts, and so does its `core.hooksPath` pin. The test and e2e fixtures copy the pattern. So the product would fail the same way on Windows once the generator got past it. Assumption, not verified on a Windows machine: Git for Windows maps the spelling `/dev/null` to `nul` in its own `open` and `fopen`.

## Work to do

- One constant, `GIT_NULL = "/dev/null"`, in `src/core/git/run.ts`, used for the environment and the hooks pin there, and by the generator, the unit-test fixtures and the e2e fixtures.
- 02-git and ADR-012 name the spelling and why `os.devNull` is not used.

## Out of scope

- The rest of DA-45: the smoke, the e2e suite, and a required Windows job.

## Verification
