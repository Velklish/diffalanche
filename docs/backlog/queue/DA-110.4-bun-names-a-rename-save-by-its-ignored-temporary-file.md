# DA-110.4 · Under Bun a working-tree file saved by rename through a temporary name git ignores is not heard

- **Order:** 810
- **Scope:** [05-watcher](../../reference/05-watcher.md#one-watch-per-directory-on-linux)
- **Created:** 2026-09-29
- **Dependencies:** none
- **Parent:** DA-110.3
- **Cost:** major

## Context

Finding discovered while working on DA-110.3. Bun 1.3.14 on Linux reports one name
per read of the inotify descriptor, and for a rename that name is the source. DA-110.3
made the repository's rules keep git's `index.lock` and `HEAD.lock` and every file of
`.git/info` for that reason. A working-tree file saved the same way has no such rule:
all the burst holds is the temporary name. Where the repository's `.gitignore`
ignores that name, `check-ignore` calls the whole burst ignored and nothing is
rescanned.

Evidence, run by the worker on the DA-110.3 branch: `wt.mjs` in that run's
scratchpad (`t1103/`) is `watchTree` with `repositoryIgnore` over a fresh repository,
and saves `src/a.ts` three times by `printf > src/a.ts.tmp && mv src/a.ts.tmp
src/a.ts` from a shell:

```
== node
-- save 1 by rename: src/a.ts.tmp src/a.ts
-- save 2 by rename: src/a.ts.tmp src/a.ts
-- save 3 by rename: src/a.ts.tmp src/a.ts
== bun
-- save 1 by rename: src/a.ts.tmp
-- save 2 by rename: src/a.ts.tmp
-- save 3 by rename: src/a.ts.tmp
```

At `f7b57b8`, before DA-110.3, Bun's own recursive watch named the temporary file
the same way (`rv1102/d.mjs`: `rename reviews/s/comments.json.tmp-…` on each
write), so this is not new with the watch per directory. The burst is dropped here:

<!-- quote:../../../src/core/watcher/index.ts -->
```ts
    // Trimmed after the answer is read, which leaves a burst larger than the
    // cap correct: what was just asked is what decides it.
    const answer = paths.every((path) => cache.get(path) === true);
```
<!-- /quote -->

End to end, by `t1103/e2e.mjs`: `serve` on the small synthetic review, `.gitignore`
set to `dist/` and `*.tmp`, then `app/shipment/shipment_88.py` of
`repos/core/cargos-api` saved twice through `shipment_88.py.tmp`. Each save's frames
on `/api/events` in the 1.5 s after it:

```
== bun serve (fix)
rename-save 1 of app/shipment/shipment_88.py via ignored .tmp: NOTHING
rename-save 2 of app/shipment/shipment_88.py via ignored .tmp: NOTHING
== node serve (fix)
rename-save 1 of app/shipment/shipment_88.py via ignored .tmp: diff-changed {"type":"diff-changed","repo":"repos/core/cargos-api",…
rename-save 2 of app/shipment/shipment_88.py via ignored .tmp: diff-changed {"type":"diff-changed","repo":"repos/core/cargos-api",…
```

The change stays unseen under Bun until another edit of the repository rescans it.
Which editors save through a temporary name beside the file, and which names they
use, is not checked.

## Work to do

- List the temporary names the common editors save through.
- Decide how a burst whose only names are ignored can still hear a rename's target
  under Bun. One option is a per-directory comparison of stamps on each event, the
  walk's baseline kept per watched directory. It costs a stat of every file of the
  named directory per event and the walk's memory, and it would make the event's name
  irrelevant on every runtime.

## Out of scope

- Node, which names the target (DA-110.3).

## Verification

- A save by rename through an ignored temporary name produces a `diff-changed` under
  Bun, three times in a row.
