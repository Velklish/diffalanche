# DA-55.5 · The first document of a server's lifetime is built from a cache nothing has refreshed

- **Order:** 760
- **Scope:** 07-server (see [reference](../../reference/README.md))
- **Created:** 2026-09-21
- **Dependencies:** none
- **Parent:** DA-55.3
- **Cost:** major

## Context

Found while implementing DA-55.3, and it is the boundary of that fix rather than
a defect it introduced.

DA-55.3 established the rule: **a cache that matches on base and scope is not
thereby fresh.** `sameBase` and `sameScope` say `diff.json` was computed for the
question this session asks; nothing in them compares it with the working tree.
The only thing that refreshes a change set is the watcher, so the fix reads the
working tree for every session the watcher does not follow, and trusts the
cache only for the one it does:

<!-- quote:../../../src/server/review.ts -->
```ts
  if (followed) {
    const adopted = entry.adopted;
    if (adopted !== null && answers(adopted, review)) return adopted;
    const cached = await readDiffCache(config.dataDir, session);
    if (cached !== null && answers(cached, review)) return cached;
  }
  return rebuild(config, session, review);
```
<!-- /quote -->

That exemption is sound *while the server runs*. **At the moment it starts,
nothing has refreshed the followed session's cache either.** `diff.json` of the
current session is whatever the last write left there, and the working tree has
moved freely since with no diffalanche running: the person edited code, an agent
committed, a branch was switched.

The path, established by reading it rather than by measurement:

- `startReviewServer` warms the document before the socket opens — the
  `review.document()` call in [src/server/serve.ts](../../../src/server/serve.ts).
- By then the watcher is started, so `watched()` answers with its session and
  `changeSet` takes the `followed` branch above.
- `answers()` compares base and scope and nothing else:

<!-- quote:../../../src/server/review.ts -->
```ts
function answers(cache: DiffCache, review: Review): boolean {
  return sameBase(cache.base, review.base) && sameScope(cache.scope, review.scope);
}
```
<!-- /quote -->

Both match — neither the base nor the scope changed while the server was down,
only the code did — so the stale cache is served. It is the same shape as the
defect DA-55.3 fixed, pointed at the current session instead of a named one, and
bounded by the window before the watcher's first rescan of a repository: a
person who edits with the server stopped, then starts it, sees the change set of
the previous session until they touch a file in that repository.

**Why it is a boundary and not a regression.** Before DA-55.3 the warm-up ran
*ahead* of `startWatcher`, so `watched()` answered `null` and the startup build
scanned — by accident of ordering, not by decision. DA-55.3 moved the warm-up
behind the watcher deliberately, so that `watched()` has an answer at that
point. That made the exemption explicit, and this entry is the boundary it made
visible. It was left alone there because DA-55.3's own verification requires a
window on the current session to be unaffected — "same numbers before and
after" — and a scan at every `serve` is a cost the owner chooses.

**What is not established.** How often a real restart lands after an edit, and
what a scope scan at every `serve` would cost on a real root. The synthetic
fixture's whole-root scan measured 545–594 ms as DA-24.1's cold path, but that
fixture's second session has no scope; a scoped task is bounded by its own
repositories, so that number is an upper bound for a root of twenty-one
repositories and says nothing about a two-repository task.

## Work to do

- Decide whether the first build of a server's lifetime may trust `diff.json` at
  all. The candidates are not equal:
  - **Rescan the current session's scope once at startup.** Correct, and it
    makes the rule of DA-55.3 whole: at that moment nothing has refreshed any
    cache, so no cache is trusted. The cost is the scope's repositories, paid
    once per `serve`, and it is a slower `diffalanche serve` for every start,
    including the ones where nothing changed.
  - **Trust it and repair on the first rescan**, which is today. Cheapest, and
    wrong for exactly as long as nobody touches a file in the affected
    repository — which on a repository the person has stopped working in is
    indefinitely.
  - **Compare against something cheaper than a scan**: the `ResolvedBase.sha`
    each repository records in the cache against what git reports now. One
    `rev-parse` per repository instead of the five processes a read costs. It
    catches a base that moved — a commit, a branch switch — and **not** an
    uncommitted edit, so it closes part of the gap only, and the part it leaves
    open is the common one.
- Whichever is chosen, say it in [07-server.md](../../reference/07-server.md)
  beside the rule under **The review document**. The rule is stated there now
  without its startup window, and a reader will take it to cover more than it
  does.

## Out of scope

- Named tasks, which DA-55.3 closed: their change set is read from the working
  tree whenever their document is built.
- The watcher following more than one session
  ([DA-55.1](../../archive/DA-55.1-watcher-follows-one-session/task.md)), which is about
  comments and metadata and rescans none of those sessions.
- The cost of the cold path itself, which is DA-24.1's and is settled: it is
  bounded by the task's scope and paid once per session per server lifetime.

## Verification

- A server started after the reviewed code changed while it was stopped answers
  `GET /api/review` with the change that happened, not with the change set of
  the previous run. Reverting the fix turns that test red.
- The cost of starting is proportional to the current session's scope rather
  than to the root: a task over two of twenty-one repositories does not read the
  other nineteen.
- A root with no current session still starts and still opens the first-run
  screen rather than failing — `serve` catches the domain's refusal today and
  must go on doing so.
