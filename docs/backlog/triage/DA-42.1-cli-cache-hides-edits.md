# DA-42.1 · A CLI rewrite of diff.json with no server running hides an edit from re-anchoring

- **Scope:** [06-cli](../../reference/06-cli.md), [04-domain](../../reference/04-domain.md)
- **Created:** 2026-09-29
- **Dependencies:** DA-42

## Context

Finding discovered while working on DA-42. Cost: major.

Re-anchoring runs in the watcher only. It learns that a file's lines moved by comparing a repository's entry of the change set before and after a rescan. While a server runs, the watcher keeps its own memory of each entry, so a `comment` or `diff` that rewrites `diff.json` between an edit and the rescan no longer hides the edit (`tests/reanchor.test.ts`, "re-anchors an edit a CLI command wrote into diff.json before the rescan came").

With no server running there is no such memory. An agent edits a file, runs `diffalanche diff --json` or `diffalanche comment`, and both rewrite `diff.json` from the working tree (`refreshRepository` and the `diff` command, `src/core/change-set.ts`, `src/cli/commands/diff.ts`). When a server starts later, its whole read compares the working tree with that rewritten `diff.json`, finds nothing moved, and every comment on the edited file stays on its old line number, now pointing at other code. Nothing marks it orphaned either.

Evidence: reasoning from the code paths named above, not reproduced by a test. `docs/reference/04-domain.md`, "What it does not do yet", names the gap.

## Work to do

- Decide where re-anchoring runs for a CLI writer of `diff.json`: in the writer itself (the entry it replaces is the `before` of a pass, at the cost of blame in `comment` and `diff`), or by keeping the anchors' own revision on disk so any later reader can tell.
- Implement it, and hold the scenario above in a test: an edit, a `diff --json`, then a server start, and the comment on the new line.

## Out of scope

- The model proposal and the UI (DA-43).

## Verification

- Vitest: edit a commented file, run `diff` through `run()`, start a watcher and `refresh()` it; the comment is on its new line or `orphaned`, never on its old number with other code under it.
