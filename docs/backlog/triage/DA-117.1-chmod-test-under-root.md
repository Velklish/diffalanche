# DA-117.1 · The unreadable-reviews test takes the right away with chmod, which root keeps, so it is red in every cloud session

- **Scope:** 05-watcher (see [reference](../../reference/README.md))
- **Created:** 2026-09-28
- **Dependencies:** none
- **Parent:** DA-117
- **Cost:** major

## Context

`tests/watcher.test.ts` › "keeps what it knew when `reviews/` cannot be listed, and
does not empty it" makes the listing fail with `chmodSync(reviews, 0o000)` and then
expects `snapshotSessions` to answer `null`. A process running as root lists a
directory whatever its mode, so on a Claude Code on the web container (`id -u` is 0)
the listing succeeds and the test reads `Map { 'synth' => 'open' }` where it expects
`null` — red in `bun run test` and `bun run test:bun` on DA-82's tree and on the base
`f49b3fa` alike (DA-82's result). What the test holds is right; the way it makes the
listing fail is not a way that works for every user.

## Work to do

- Make the listing fail in a way root cannot bypass — the failure injected at the
  read the watcher makes, rather than through the file mode — keeping the assertion.

## Out of scope

- Skipping the test under root: that stops it holding anything where it is red.

## Verification

- The test passes as root and as an ordinary user, and fails on both when
  `snapshotSessions` is made to empty the map on a failed listing.
