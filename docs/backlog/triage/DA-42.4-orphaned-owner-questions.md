# DA-42.4 · Owner questions on orphaned comments: return on their own, resolved ones, and who re-anchors

- **Scope:** [04-domain](../../reference/04-domain.md), `docs/SPEC.md` section 3, decision 8, and section 5, Phase 3
- **Created:** 2026-09-29
- **Dependencies:** DA-42

## Context

Finding discovered while working on DA-42, from its review. Three forks of re-anchoring are product
decisions, and DA-42 took the conservative side of each without writing it into the spec. What the
tool does today is in [04-domain.md](../../reference/04-domain.md), "Re-anchoring", named there as
waiting for the owner.

What the spec says:

<!-- quote:../../SPEC.md -->
- After code edits, comments stay on their lines. A comment whose place cannot be found is marked `orphaned` and kept.
<!-- /quote -->

What the handoff says, in "Orphaned" and in "Live edits":

<!-- quote:../../design/HANDOFF.md -->
- **Orphaned.** Три уровня переанкоровки: `git blame --reverse` от базового коммита к рабочему дереву, затем фаззи-матч по сохранённым `lineContent`/`before`/`after`, и только потом модель. Модель отдаёт номер строки, кандидата и confidence — комментарий не переезжает сам, человек подтверждает.
<!-- /quote -->

<!-- quote:../../design/HANDOFF.md -->
- **Live-правка в открытом файле** не сбрасывает позицию чтения и не закрывает композер. Изменившиеся ханки помечаются: заголовок ханка получает акцентную рамку и подпись вида `обновлено 3s ago`, событие уходит в ленту активности. Комментарии, потерявшие строку, переходят в `orphaned` — молча их не переносить.
<!-- /quote -->

**Q1. Does an orphaned comment go back to `open` on its own when its text comes back?** Today it
does not: a pass never places an orphaned comment again, even when the stored line and context
reappear exactly where it was. One consequence to weigh: `git stash` of a tracked file with a
comment on an added line orphans that comment — the file reads, and the line is not in it — and
`git stash pop` does not bring it back. The handoff's "a comment never moves on its own" reads for
keeping it; "comments stay on their lines" reads for letting a unique exact match return it.

**Q2. Does a resolved comment whose line is gone become `orphaned`?** Today it stays resolved where
it was: its status is a human's verdict and its place is history. The handoff's live-edit rule
names comments that lost their line without a status, and could be read to cover resolved ones.
A resolved thread left behind this way reopens only with `--line` (`reopen` checks that its anchor
still reads at its line).

**Q3. Is `reopen --line` a human's only?** Today it is, since `reopen` is (`docs/SPEC.md` section 3,
decision 8: only a human sets `resolved`, and the CLI refuses `resolve` and `reopen` unless the
caller passes `--role human`). The orchestrator of DA-42 took this as following from decision 8; it
is listed here so the owner sees it beside the other two. An agent that fixed code it could no
longer find a comment's line in can only say so in a reply.
