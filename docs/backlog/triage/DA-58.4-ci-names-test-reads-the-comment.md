# DA-58.4 · tests/ci-names.test.ts reads the required check names out of a 27-line comment in ci.yml, so the comment cannot shrink

- **Scope:** [11-perf](../../reference/README.md)
- **Created:** 2026-09-28
- **Dependencies:** none

## Context

Finding discovered while working on DA-58, in the sweep of `.github/`. Cost: major — it blocks the last block of that area, and with it the comment gate DA-58 turns on when the count is zero.

The header comment of `.github/workflows/ci.yml` lists the check-run names a branch protection rule has to name, one per line, indented by five spaces — 27 lines in one `#` block, the longest in the area. The sweep moved that text to [11-perf.md](../../reference/11-perf.md), "The checks a pull request requires", as a table, and shrank the comment to a two-line pointer. That turned `tests/ci-names.test.ts` red, because the test takes the list from the comment itself:

<!-- quote:../../../tests/ci-names.test.ts -->
// The names branch protection matches are written once, in the header comment, indented by
// five spaces. A trailing `<- the job id is x` note is prose about the name, not part of it.
<!-- /quote -->

and holds a sentence of it verbatim:

<!-- quote:../../../tests/ci-names.test.ts -->
    expect(ci).toContain("is deliberately not in the list until DA-45");
<!-- /quote -->

The comment is data the suite parses, so shrinking it needs a change to the test, which is code in `tests/` — outside a comment sweep and outside the `.github/` track. The sweep put the 27 lines back as they were, so the suite is green and `bun scripts/check-comments.ts .github` reports this one block; the table in 11-perf.md is written and is, for now, a second copy of the list.

## Work to do
