# DA-16.1 · The scrolling budget is red on main

- **Scope:** 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-05
- **Dependencies:** DA-16

## Context

`bun run perf` fails on `main` at f93a422 — with none of the server work on it —
on the same machine, minutes apart from a green run of the same gate against the
Phase 0 page. Measured while the Phase 1 run had several agent sessions working
on this machine:

```
main f93a422 (UI of DA-19, DA-20, DA-21)
  run 1  cpuPerFrameMs 7.9   scrollLongTasks 0
  run 2  cpuPerFrameMs 9.1   scrollLongTasks 1
  run 3  cpuPerFrameMs 9.5   scrollLongTasks 3
  median 9.1 ms (budget 8.3)   long tasks 1 (budget 0)   FAIL

worker branch at 731a6bc (DA-12 and DA-16 on top of the same UI)
  median 9.5 ms, long tasks 0   FAIL
  and, an hour earlier: 8.9-9.5 ms, 0-1 long tasks
```

For comparison, the same gate on the Phase 0 page earlier the same hour, on the
same machine: 6.9, 7.1, 7.0 ms per frame and zero long tasks.

Two readings are open and this finding does not choose between them: the UI the
Phase 1 wave landed costs more per scrolled frame than the spike's page did, or
the machine was busy enough to add a millisecond. They are separated by one
measurement on a machine doing nothing else, which is the first step below.

`docs/SPEC.md` section 6 makes the budget a gate, so this blocks every task that
has to report green gates until it is settled.

## Work to do

- Run `bun run perf` on `main` on an idle machine, three runs, and record the
  median. If it is inside 8.3 ms, the failure is contention and the gate needs
  to say so — a note in [11-perf.md](../../reference/11-perf.md) about what the
  numbers mean on a busy machine, and nothing else.
- If it is over, find what the new page spends the frame on — the `PerformanceObserver`
  entries of the harness name the long tasks — and bring it back inside the
  budget. The suspects are what DA-19 to DA-21 added around the diff: the
  sidebar, the thread rail, and the per-file state of the shell.

## Out of scope

- Changing the budget. It is `docs/SPEC.md` section 6 and a spec change is the
  owner's.

## Verification

- `bun run perf` green on an idle machine, three runs, on `main`.
