# DA-82.2 · perf/run.ts --runs 3 hangs in its second repetition on the 4-core container, base included

- **Scope:** 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-28
- **Dependencies:** none
- **Parent:** DA-82
- **Cost:** major

## Context

[11-perf.md](../../reference/11-perf.md#the-measurement-harness) documents
`bun perf/run.ts --runs 3` as the way to take several raw rows in one server. On the
4-core cloud container of 2026-09-28 (Chromium 141 headless shell) it did not finish:

- on DA-82's tree, `timeout 400 bun perf/run.ts --fixture .perf/fixture --runs 3`
  printed run 1 and run 2's three jumps, then nothing until the timeout (exit 124);
  an earlier invocation stayed idle for over six minutes with no Chromium process
  left and the load average at 0.01;
- on `origin/main` at `f49b3fa`, in a worktree of its own, the same command printed
  run 1 only and was killed by the same timeout (exit 124);
- `--runs 2` on DA-82's tree finished once (exit 0).

The gate and `perf/compare.ts` are not affected: they start one `perf/run.ts
--runs 1` process a repetition (`measureOnce`). Where the second or third
repetition stops — the cold switch, the measured switch pair or the update, which
come after the jumps in `measure` — has not been looked at; `printLaps` prints only
at the end, so a hung run says nothing about its step. It has not been tried on
the development machine.

## Work to do
