# DA-76.1 · A file that changes type is two entries for one path, and the de-duplication does not see it

- **Scope:** 02-git (see [reference](../../reference/README.md))
- **Created:** 2026-09-18
- **Dependencies:** none

## Context

DA-76 made one path one entry where the two *sources* of the change set named it
twice — the diff and `ls-files --others`, which `git rm --cached` makes collide.
The de-duplication is in that loop and compares untracked paths against the paths
the diff already carries.

A type change produces the same duplicate from **one** source, so nothing in that
loop is reached. Git cannot express file → symbolic link as a single patch, so it
prints two, both for the same path. Reproduced on git 2.54.0 (Apple Git-157), a
tracked `thing.txt` replaced by a link to `/etc/hosts`:

```
$ git diff-index -p -M <sha> --no-color --no-ext-diff --no-textconv -U3
diff --git a/thing.txt b/thing.txt
deleted file mode 100644
…
-real content
diff --git a/thing.txt b/thing.txt
new file mode 120000
…
+/etc/hosts
$ … | grep -c '^diff --git'
2
```

And through the reader, `readRepositoryChange(root, "r", { mode: "head" }, { hunks: true })`:

```
[{"path":"thing.txt","status":"deleted","hunks":1},
 {"path":"thing.txt","status":"added","hunks":1}]
warnings: []
```

Two entries, no warning. Every consequence DA-76 lists follows: the counters
count the path twice, the card key and the sidebar row key repeat, and
`findFile` takes the first match, so a comment on the new side of the link
anchors against the deletion.

The reach is narrower than DA-76's. `git rm --cached .env` is an ordinary thing
to do; replacing a tracked file with a symbolic link is not, and it was not seen
in a real session — the entry is written from a deliberate probe. What makes it
worth a card is that [02-git.md](../../reference/02-git.md) now says "One path is
one entry" without qualification, and since DA-73 a link is a first-class shape
of the change set rather than something the reader refuses.

## Work to do

- Decide what one path with a deletion and an addition of a different mode
  should be. The candidates are the same three DA-76 weighed and they do not
  resolve the same way: the pair is not "the same content twice" but two real
  halves of one change, and dropping either loses what the reviewer needs — the
  content that left, or the link that arrived.
- Put the decision where the entries are built — `parseDiff` splits the diff into
  one patch per file, and this is the one case where that is not one patch per
  *path* — rather than in a consumer.
- Say in [02-git.md](../../reference/02-git.md) what the qualification to "one
  path is one entry" is; the sentence pointing at this entry is already there.

## Out of scope

- `git rm --cached`, which is DA-76 and is closed.
- Mode-only changes, which git prints as one patch and which already carry
  `modified` correctly.

## Verification

- A test builds a repository where a tracked file becomes a symbolic link and
  asserts whatever the decision above settles on; the probe above is the fixture.
- `bun run lint`, `bun run typecheck`, `bun run test`, `bun run test:bun`.
