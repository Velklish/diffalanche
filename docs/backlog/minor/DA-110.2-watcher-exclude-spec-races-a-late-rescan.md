# DA-110.2 · watcher.test.ts' .git/info/exclude case can meet the rules write's own late rescan

- **Scope:** 05-watcher
- **Created:** 2026-09-29
- **Parent:** DA-110
- **Cost:** minor

## Evidence

Finding discovered in `check` of Velklish/diffalanche#9, run 36518900694, on a commit that changed only docs. The same code had passed on the commit before, and passed again on a re-run. `tests/watcher.test.ts` › "says nothing about a path .git/info/exclude names" (added in `696ef1c`) failed at its `expect(changesOf(mark, REPO)).toEqual([])`:

```
+   {
+     "at": 5658.8338,
+     "event": {
+       "files": [
+         ".git/info/exclude",
+       ],
+       "repo": "repos/core/cargos-api",
+       "type": "diff-changed",
```

The event that arrived after `mark` names the rules file itself. It is not a `coverage/` path, so the test saw a second rescan caused by the rules write, landing after its `waitForChangeOf` and `settle()`. Assumption, not reproduced: the write of `.git/info/exclude` produced two watch events far enough apart that the debounce answered them with two rescans.

## Work to do

- Make the case wait until the rules write's rescans are over before the burst under test, or filter its assertion to events that name `coverage/`. Say which one, and why it still fails when an excluded path is reported.
