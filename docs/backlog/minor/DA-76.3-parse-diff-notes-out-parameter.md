# DA-76.3 · notes is an out-parameter of parseDiff, so a caller that forgets it drops the warning without a sound

- **Scope:** 02-git (see [reference](../../reference/README.md))
- **Created:** 2026-09-21
- **Parent:** DA-76.1
- **Dependencies:** none
- **Cost:** minor

## Context

Found by the review of
[DA-76.1](../queue/DA-76.1-type-change-is-two-entries-for-one-path.md). Merging
the two halves of a type change made one of them disappear from the change set
when it is binary or too large, and the evidence that it was skipped is a
repository warning. DA-76.1 delivers that warning through a new optional
`notes` array on `PatchOptions`: the caller supplies the sink, `parseDiff`
appends to it.

`parseDiff` is otherwise pure, and it is public through
[src/core/index.ts](../../../src/core/index.ts). Exactly one production caller
passes the array today — the change-set scan in
[src/core/git/index.ts](../../../src/core/git/index.ts) — and `readUntracked`
correctly does not, because a parse of one patch can never merge anything. So
the code is right as it stands.

What is missing is any way for the next caller to be wrong noisily. An
out-parameter that is optional cannot be forgotten with a compile error, and
the thing lost by forgetting it is the only sign that half a change set is not
on screen. DA-76.1 writes the obligation down in
[02-git.md](../../reference/02-git.md); a line of documentation is the weakest
of the two available guards, and it is the one that fitted inside a task about
the core merge.

## Work to do

- Return `{ files, notes }` from `parseDiff` instead of taking a sink, so the
  warning cannot be dropped by omission. The cost is the two call sites and
  the `parseDiff` assertions in `tests/git.test.ts`.
- Decide it as a contract change, not as a refactor: `parseDiff` is exported
  from the package root, and the shape of its return is what callers outside
  this repository would see.

## Out of scope

- The merge itself and the warning's wording, which are DA-76.1 and are done.
- The other readers of `PatchOptions`. Only the notes sink has this shape.

## Verification

- A caller that does not take the notes out of `parseDiff` does not compile.
- The warning still reaches `warnings` ahead of the untracked ones, which is
  what lets the existing verdict in `tests/git.test.ts` assert the list
  exactly.
- `bun run lint`, `bun run typecheck`, `bun run test`, `bun run test:bun`.
