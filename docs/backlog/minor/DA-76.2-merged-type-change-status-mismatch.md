# DA-76.2 · A merged type change is "modified" in the core and "add" in the renderer, and the card is sized from one while it is drawn from the other

- **Scope:** 08-ui (see [reference](../../reference/README.md))
- **Created:** 2026-09-21
- **Parent:** DA-76.1
- **Dependencies:** none
- **Cost:** minor

## Context

Found by the review of [DA-76.1](../queue/DA-76.1-type-change-is-two-entries-for-one-path.md), which merged the two
entries a type change used to produce into one. Where one half is omitted —
binary, or too large — the merged entry now carries a single patch, and that is
the shape this entry is about.

`mergedPatch` in [src/ui/patch.ts](../../../src/ui/patch.ts) returns early when
there is one patch to merge, so `parsed.type` stays whatever the parser said:
`add` for the surviving link half. `ReactDiffFile.tsx` passes that value on as
`diffType`, and the renderer draws one column in the split view.
`FileCard.tsx` sizes the code column from `file.status`, which after DA-76.1 is
`"modified"` — the two-column arithmetic. With wrapping on, `measurePatch`
therefore wraps at roughly half the width the renderer actually uses.

**Nothing drifts visibly today, and the reason is the part worth keeping.** The
half that can be binary or too large is always the regular-file half, so the
half that survives is always the symlink: one short line, and nothing wraps at
either width. Before DA-76.1 the two numbers agreed for a different reason —
that half was its own `added` entry, and both sides read the same status.

So the defect is latent by construction, and it stops being latent on the day
a surviving half is long enough to wrap. Nothing in the code says that day
cannot come; only the shape of a symlink does.

The fix was kept out of DA-76.1 deliberately. It is UI work, and that batch
carried no UI coverage of its own; a fixture written against today's behaviour
would have pinned the mismatch as expected rather than closed it.

## Work to do

- Give `mergedPatch` the entry's status, or a flag, so a merged entry reads
  `modify` however it was built — one patch or two.
- Add a fixture to `tests/ui-type-change.test.ts`
  for the single-patch merged shape. The file has none, and the core verdict
  DA-76.1 added does not reach the UI side at all.

## Out of scope

  lock", which are [DA-80](../queue/DA-80-one-repository-patch-implemented-twice.md).
