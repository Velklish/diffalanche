# DA-42.5 · A plain mv is not followed: the comment is orphaned on the deleted path

- **Scope:** 04-domain, 02-git (see [reference](../../reference/README.md))
- **Created:** 2026-09-29
- **Parent:** DA-42
- **Cost:** minor

## Evidence

Found while working on DA-42's review fixes. A file moved with `git mv` is a rename in git's diff,
and re-anchoring carries its comments to the new path. A file moved with a plain `mv` is not: the
reader reports the old path as a deleted tracked file and the new one as an untracked addition,
because `diff-index` never sees an untracked file and the untracked files are read beside it without
being paired (`docs/reference/02-git.md`, "Untracked files"). `tests/reanchor.test.ts`, "reads a
plain mv as git does, a deletion and an untracked file, and orphans the comment", holds what happens:
the comment is orphaned.

An agent that renames with its own file tools, rather than `git mv`, is the common case of this.
Pairing a deletion with an addition whose text is close — what git's `-M` does for tracked files —
would be rename detection of the tool's own, with a threshold of its own to justify.
