# DA-58.1 · Thread widgets under a line animate with dcin, though the stylesheet says they must not

- **Scope:** 08-ui, 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-28
- **Parent:** DA-58
- **Cost:** major (hypothesis)

## Evidence

Found in the DA-58 sweep of `src/ui/styles.css`, as a stale comment whose fix is a code change. The
block above the rule said, in full, before the sweep shortened it:

> Only in the rail, where a card appearing is news. Under a line it appears because the card was
> scrolled to, and animating every widget a mounting card brings with it costs more CPU per
> scrolled frame than the budget of `docs/SPEC.md` section 6 has.

The rule under it animates both, and the rail's rule is then written a second time on its own:

<!-- quote:../../../src/ui/styles.css -->
.rail-list .thread,
.thread-widget .thread {
  animation: dcin 160ms ease-out;
}

.rail-list .thread {
  animation: dcin 160ms ease-out;
}
<!-- /quote -->

`git log -S "thread-widget .thread {" -- src/ui/styles.css` names only `696ef1c`, the squash the
repository starts from, so the history does not say which of the two is the decision: the second
rule reads like the rail-only version, and the first like a later edit that widened it
(`DESIGN.md`: "use `dcin` for anything that appears").

Hypothesis, not measured: if the comment's measurement still holds, every widget a mounting card
brings animates during the scroll run, and the scroll line of the perf gate pays for it. The gate
has been green with the rule as it is, so either the cost went away with later changes (DA-115
removed the page's other animation) or the comment's claim was never true of this selector.

What settles it: the scroll run of `bun run perf` on a quiet machine with `.thread-widget .thread`
dropped from the first selector against the rule as it is, three runs a side. Then either the
selector goes (and the duplicate rule with it), or the comment above it is rewritten to say that
widgets animate and why that is affordable.
