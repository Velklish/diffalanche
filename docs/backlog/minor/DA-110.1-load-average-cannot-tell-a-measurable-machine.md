# DA-110.1 · The load average cannot tell a machine the harness measures well on from one it does not

- **Scope:** 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-24
- **Parent:** DA-110
- **Cost:** major (hypothesis)

## Evidence

Finding discovered while working on DA-110, measured by worker:perf1 of run 0923 on one
8-core M1 Pro — six performance cores and two efficiency cores — under `/tmp/da-perf.lock`.

The same tree, `5e0ee24`, on two mornings at about the same load average:

| when | one-minute average | CPU per frame | update after an edit | source |
|---|---|---|---|---|
| 2026-09-22 | 7.52 and 8.82, entry of two gate runs | 9.3 and 10.3 ms | 330 and 391 ms | DA-110's card |
| 2026-09-24 05:30–05:34 UTC | 4.8–7.6 across three gate runs, five-minute 6.8–7.7 | 7.8–7.9 ms | 275–287 ms | alternated with `f9cda1b`, which read 8.0 ms and 284–286 ms |

About one runnable task per core both times, and a quarter apart on the lines that matter.
The precondition of [ADR-013](../../adr/adr-013-perf-gate-off-ci.md), even with the five-minute
figure DA-54.5 added, passes both mornings, and no single ceiling on either figure can separate
them: the quiet morning's own readings, taken every five seconds, reached 1.3 per core with
the gate's run on it.

Hypothesis, not tested: the load average counts runnable threads on all eight cores alike, and
what the harness gets depends on whether its threads — the browser's renderer above all — run on
the performance cores. A machine whose other load is background work that macOS keeps on the
efficiency cores leaves the performance cores to the harness; one whose other load is other
sessions' test suites at default priority does not. On 2026-09-24 the other load was mostly
`mediaanalysisd`, a background daemon, at about 70 % CPU, and a browser's agent process at about
100 %, whose priority nobody read. The count cannot say which, and the spread of the harness's
own repetitions may: Run B of the card spread 349 / 391 / 470 ms on the update line where the quiet
window's single processes spread 257–341 over forty.

What settles it: gate runs at matched load averages with the other load pinned to one kind of
core — background work (`taskpolicy -b`) against default-priority work — and, if the hypothesis
holds, whether the spread of the gate's own five repetitions is a better "not evidence" signal than
any load figure.
