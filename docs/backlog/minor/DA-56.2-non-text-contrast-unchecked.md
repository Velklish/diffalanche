# DA-56.2 · Non-text indicators have no contrast check: the design test covers text only, and WCAG 1.4.11 wants 3:1

- **Scope:** 08-ui (see [reference](../../reference/README.md))
- **Created:** 2026-09-10
- **Dependencies:** none
- **Cost:** minor

## Context

Found in DA-56, while closing a neighbouring hole rather than by looking for this one.

[tests/design-contrast.test.ts](../../../tests/design-contrast.test.ts) is the repository's only contrast check, and it is a check on **text**: `AA = 4.5`, pairs of a text colour against the backgrounds it actually sits on, plus `FILLED` for the six filled badges where the text is `onAcc` and its background is the badge. It does what it does well — DA-56 added `--tx2` and `--tx3` on `--accBg` to it, because a closed task's name on the row this window is showing lands exactly there, and the tightest new pair is `tx3` on `accBg` at 4.87 against the 4.5 bound.

What no test covers is a mark that carries meaning **without** being text. DA-56 added one: the dot on the session pill that says a task appeared. The counter dots are the same shape of thing. WCAG 2.2 asks 3:1 of such indicators under 1.4.11 — a different threshold from text and a different set of pairs, since what matters is the indicator against what is behind it rather than a glyph against its ground.

This is not a claim that any of them fails. Nobody has measured them, which is the entry: the repository has a rule for text contrast that a test enforces, and a rule for non-text contrast that exists only in `DESIGN.md`'s prose, if at all.

DA-55 left a related finding — `--acc` outside the contrast test — and DA-56 closed the half of it that is about text on `accBg`. This is the half that remains, stated properly: `--acc` in the role of an indicator, not of a background under a label.

## Work to do

- List the non-text indicators the interface actually has: the history mark, the counter dots, the partial-selection glyph in the scope editor and the tree, the focus ring if it is the only signal anywhere, and the hairline between repository sections if it carries meaning rather than decoration.
- Measure each against what is behind it, at the 3:1 of 1.4.11, in both themes. The formula is in the existing test and does not need a second implementation.
- Put the ones that carry meaning under the same test, in their own group with their own bound — not by lowering `AA`, which would weaken the text check to accommodate a different rule.
- If any of them is decoration rather than information, say so where the token is defined; a reader cannot tell the two apart from the code, and the next person to add a dot will copy whichever one they find first.

## Out of scope

- Text contrast, which is checked and which DA-56 extended.
- Choosing new colours. This entry is about knowing the numbers; changing them is whatever it finds.

## Verification

- Every non-text indicator that carries meaning has a measured ratio in both themes, and the ones below 3:1 are either fixed or recorded as a deliberate exception with a reason.
- Breaking one on purpose — a dot moved to a background it cannot hold — turns the test red.
