# DA-37.2 · A thread on the old side is drawn under the new-side line of the same number

- **Scope:** 08-ui (see [reference](../../reference/README.md))
- **Created:** 2026-09-23
- **Parent:** DA-37
- **Cost:** minor

## Evidence

Finding discovered while working on DA-37, by reading; not reproduced in a browser. The card
groups its threads by line number without looking at `side`:

<!-- quote:../../../src/ui/components/FileCard.tsx -->
    const line = thread.endLine ?? thread.line;
<!-- /quote -->

and the rows they are put under are keyed by the new-side number alone:

<!-- quote:../../../src/ui/renderers/ReactDiffFile.tsx -->
      const line = computeNewLineNumber(change);
<!-- /quote -->

A comment written with `diffalanche comment --side old --line N` on a deleted line — the
CLI's `--side` is documented — would therefore sit under whatever line carries new-side
number N, or nowhere. The UI itself writes `new` from the diff; since DA-37 browse mode writes
`old` at the base, and draws those threads by side in its own view, so the gap is only the
card's. The fix is to key the grouping by side as well and place an `old` thread by
`computeOldLineNumber`.
