# DA-42.3 · The re-anchoring pass after every changing rescan is not measured against the update budget

- **Scope:** 05-watcher, 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-29
- **Parent:** DA-42
- **Cost:** minor (hypothesis)

## Evidence

A hypothesis, not measured: DA-42's brief said to measure nothing in perf, and the worker ran no
`bun run perf`.

After every rescan that changed a repository's entry, the watcher now queues a re-anchoring pass
(`docs/reference/05-watcher.md`, "Re-anchoring" and "Budget"): a read of `review.json` and
`comments.json` — about 100 KB on the synthetic review's 200 comments — and, per changed file with a
line comment, a read of the file and a `git blame` with its `config --list`, then a `comments.json`
write when anything moved, which comes back as a burst of the data directory, `comment-status`
frames, and a thread re-read per moved comment on an open page. The pass runs after the
`diff-changed` frame and outside the rescan queue, so it is not on the measured path by
construction; what it can cost is CPU taken from the page's render of the patched diff, and a
following edit's rescan, on the same machine.

Check: `bun perf/compare.ts` of DA-42's commit against its base on the development machine, with the
perf edit landing on a file of the synthetic review that carries line comments; if the update line
moves by more than its spread, the pass waits for the page's next frame, or is folded to one per
burst window.
