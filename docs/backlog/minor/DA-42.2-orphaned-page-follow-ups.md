# DA-42.2 · What the page and its routes still lack for orphaned comments, for DA-43

- **Scope:** 07-server, 08-ui (see [reference](../../reference/README.md))
- **Created:** 2026-09-29
- **Parent:** DA-42
- **Cost:** minor

## Evidence

Found while working on DA-42, which put `status: "orphaned"` on disk and left the page to DA-43. What
DA-43 meets when it starts, each checked in the code of DA-42's commit:

- `POST /api/comments/:id/reopen` takes a note and nothing else (`src/server/app.ts`, `verdict`), so
  the domain's `reopen` with a `line` — the one way an orphaned comment is put back on a line — is
  reachable from the CLI only. The route does read the repository again and reopens a thread whose
  anchor no longer reads as `orphaned` (`docs/reference/07-server.md`, "Writing"); what it cannot do
  is take the line a human picks, which `Find new place` of the handoff needs.
- DA-42 already counts an orphaned thread as open on the page — the tabs of the thread rail, the
  file card's and browse view's severity paint, the reading order `J`/`K` walks, the export's count,
  the scope editor's question — through the core's `isOpen`, so none of that is left here.
- `countReview` counts orphaned comments among the open ones, as `docs/SPEC.md` section 3,
  decision 8 says, and has no count of them alone: neither the sidebar nor the header can show how
  many there are without a field of their own (`src/core/domain/counters.ts`; adding one changes
  every `Counters` literal under `src/ui`, `tests/` and `e2e/`, which is why DA-42 did not).
- The search's `comment · orphaned` tag still waits for the status (`src/ui/search.ts`, the comment
  above the tag list; `docs/reference/08-ui.md` now says the status is on disk).
- A thread re-anchored to other lines arrives as `comment-status` and is re-read whole; nothing tells
  the card it moved, so the `re-anchored` marker of `docs/design/HANDOFF.md` section 3 has no source.

Assumption, not checked in a browser: the page renders an orphaned thread like an open one at its
old line, since the card knows only `resolved` as a state of its own; the orphaned card is DA-43.
