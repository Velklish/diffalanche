# DA-99.2 · config.json and the reviews/ listing rethrow a raw errno where the session files word it

- **Scope:** 03-storage (see [reference](../../reference/README.md))
- **Created:** 2026-09-23
- **Parent:** DA-99.1
- **Cost:** minor

## Evidence

Found by the review of DA-99.1. That fix words `EACCES`, `EPERM` and `ENOTDIR`
for `sessionExists` and the reads of `review.json`, `comments.json`,
`diff.json` and `current`. Two reads of the data directory go around it and keep
the `ENOENT`-only shape DA-99.1 replaced.

The configuration reads `config.json` itself:

<!-- quote:../../../src/core/config/index.ts -->
```ts
  try {
    text = await readFile(file, "utf8");
  } catch (error) {
    if ((error as NodeJS.ErrnoException).code === "ENOENT") return {};
    throw error;
  }
```
<!-- /quote -->

The listing of `reviews/`:

<!-- quote:../../../src/core/storage/index.ts -->
```ts
  try {
    entries = await readdir(dir, { withFileTypes: true });
  } catch (error) {
    if (isMissing(error)) return { names: [], warnings: [] };
    throw error;
  }
```
<!-- /quote -->

Reproduced on the worker branch after DA-99.1 (`ad75a25`), with
`XDG_CONFIG_HOME` pointed at an empty directory and `DIFFALANCHE_DATA_DIR`
empty:

```
$ bun src/cli/index.ts review list --root <a>     # <a>/.diffalanche/reviews is a file
Error: ENOTDIR: not a directory, scandir '<a>/.diffalanche/reviews'
    at async listSessionNames (src/core/storage/index.ts:374:21)
exit 2
$ bun src/cli/index.ts review list --root <b>     # <b>/.diffalanche is a file
Error: ENOTDIR: not a directory, open '<b>/.diffalanche/config.json'
    at async readConfigFile (src/core/config/index.ts:157:18)
exit 2
```

## What it would take

The listing is storage's own and can take the same `readError` as `exists` and
`readText`. `config.json` is read by the configuration module, whose refusals are
`StorageError` too (it uses `asObject` and `parseJson` of storage's fields), so it
can word the same codes with the same shape; whether it should reuse storage's
table or keep its own is the question to answer first. Either way `EISDIR` stays
out, for the reason `docs/reference/03-storage.md` gives.
