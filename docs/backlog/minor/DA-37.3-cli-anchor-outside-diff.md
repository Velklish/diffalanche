# DA-37.3 · Whether an agent's comment may anchor on a line outside the change set is not decided

- **Scope:** 04-domain, 06-cli (see [reference](../../reference/README.md))
- **Created:** 2026-09-23
- **Parent:** DA-37
- **Cost:** major (hypothesis)

## Evidence

Finding discovered while working on DA-37. The domain can now anchor a line the change set
does not carry from the file itself, when its caller passes a source:

<!-- quote:../../../src/core/domain/comments.ts -->
export type AddOptions = { source?: FileSource };
<!-- /quote -->

The server passes one, so a human's comment from browse mode lands; the CLI's `comment` does
not, so an agent asking for the same line is still refused with `line-not-in-diff`. DA-37 kept
the agent contract as ADR-004 has it rather than widen it on the way. Whether an agent should
be able to comment on context outside the diff — a caller the change did not touch, a helper
it should have used — is a decision for the owner, and until it is made the two interfaces
answer the same request differently. Hypothesis: it is wanted, because the review skill asks
agents to point at the code a finding is about.
