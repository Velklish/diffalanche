# DA-60.3 · The suites' listen().close() leaves the connection open under Bun, and the server counts the window

- **Scope:** 07-server (see [reference](../../reference/README.md))
- **Created:** 2026-09-24
- **Parent:** DA-60
- **Cost:** minor

## Evidence

Found while fixing the acceptance red of DA-55.7 (`2f4148e`). The suites read the
live stream through a helper whose close only cancels the response body:

<!-- quote:../../../tests/server.test.ts -->
```ts
    close: async () => {
      await reader.cancel().catch(() => undefined);
    },
```
<!-- /quote -->

`tests/events.test.ts` has a helper of the same shape. Under Bun, cancelling the
body does not close the connection, so the server keeps the stream subscribed and
counts the window among the tasks the watcher follows.

Measured on 2026-09-24 with a scratch script on the small synthetic review:
`startReviewServer` with `recursive: false`, then `GET /api/events?review=synth`,
one chunk read, then `reader.cancel()`, then polling `server.windows()`. On Bun,
the window was still counted 40 s later, the end of the measurement and past two
15 s heartbeats. With `AbortController.abort()` on the fetch it was gone after
52 ms on Bun and 54 ms on Node, which is what a browser tab closing does to the
connection.

It surfaced as `tests/server.test.ts`, "carries a comment the CLI wrote while no
window was on the task": with the task still counted, a burst took its snapshot,
and the CLI's comment went out as a frame. At DA-55.7's acceptance this failed
1 of 3 full `test:bun` runs at load 35–37. After `9c04e7f` made the test wait for
`windows()` to drop the task, it failed 10 of 10 on Bun ("the server never saw the
window close") until `2f4148e` closed the window with an abort.

No other test known today needs the server to see a close.

## What it would take

A test that needs the server to see a window go away closes it with an abort,
not by cancelling the body. The cheapest shape is to have both helpers take the
`AbortController` and abort in `close()`, so the next test that relies on it
cannot pick the cancel by accident. Record the rule in 11-perf, "Waits in the
suites", next to the wait on `windows()`.
