# DA-99.1 · A file where a session directory should be reaches the person as a raw ENOTDIR from exists()

- **Scope:** 03-storage (see [reference](../../reference/README.md))
- **Created:** 2026-09-18
- **Dependencies:** none
- **Cost:** minor

## Context

Found while closing [DA-99](../../archive/README.md), which wrapped the two
`mkdir` calls of `ensureDataDir` and `ensureSessionDir`. The reads next to them
were not in that task's scope and one of them has the same shape.

`exists` at [src/core/storage/index.ts](../../../src/core/storage/index.ts)
translates `ENOENT` and rethrows everything else:

```ts
async function exists(path: string): Promise<boolean> {
  try {
    await stat(path);
    return true;
  } catch (error) {
    if (isMissing(error)) return false;
    throw error;
  }
}
```

A file sitting where a session directory should be makes `stat` of
`reviews/<name>/review.json` fail with `ENOTDIR`, not `ENOENT`, so the errno
error goes out untranslated and `run()` prints its stack at exit code 2 — the
same defect DA-99 fixed one function over, and the same contradiction with
[03-storage.md](../../reference/03-storage.md): "Everything storage refuses is a
`StorageError` carrying `file` and `field`".

Reproduced on this tree at `3a248f1`, a scratch root with a session `alpha` and
a file written over `reviews/alpha`:

```
$ bun src/cli/index.ts review new alpha --root $S/root --data-dir $S/root/.diffalanche
Error: ENOTDIR: not a directory, stat '…/.diffalanche/reviews/alpha/review.json'
    at async exists (…/src/core/storage/index.ts:152:11)
    at async createSession (…/src/core/domain/sessions.ts:115:13)
EXIT=2
```

`review use alpha`, `review new beta` and `list` all end the same way, because
every one of them reaches `exists` before it reaches anything that writes. Only
`serve` gets past it, because `startReviewServer` calls `ensureDataDir` first —
which is why DA-99's own verdict on the neighbouring `EEXIST` had to be written
against `serve` rather than against `review new`.

Severity is minor and the trigger is an edge: the data directory is meant to be
edited by hand (`docs/SPEC.md` section 3, decision 5), but writing a *file* over
a session directory is a slip rather than an edit. What is wrong is the report,
not the refusal.

## Work to do

- Decide how far the translation goes on the read path. `exists` is the one
  found here; `readText` next to it has the same `ENOENT`-only shape and the
  same question. `stat` on a path under a file gives `ENOTDIR`, and on a
  directory where a file is expected `EISDIR` — the second is what
  `tests/cli.test.ts`'s "exit code 2" verdict deliberately uses, so widening
  the translation has to keep a case that still reaches exit code 2 or that
  verdict loses its subject.
- Reuse DA-99's shape rather than inventing a second one: a closed set of codes
  with their own wording, everything else rethrown.
- Say in [03-storage.md](../../reference/03-storage.md) which read failures are
  a `StorageError` and which are not; the section now says it for writes and
  leaves reads to be assumed.

## Out of scope

- The two `mkdir` calls, which are DA-99 and are done.
- Making the data directory self-repairing. Reporting what is wrong is the
  contract; fixing the file is not.

## Verification

- A file written over `reviews/<name>` makes `review new <name>` exit 1 with one
  line on stderr naming that path, and the "exit code 2" verdict of
  `tests/cli.test.ts` still has a case that reaches exit code 2.
- `bun run lint`, `bun run typecheck`, `bun run test`, `bun run test:bun`.
