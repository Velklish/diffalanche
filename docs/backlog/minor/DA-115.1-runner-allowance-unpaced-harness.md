# DA-115.1 · The runner allowance rests on a 60 Hz reading, and no runner has read the unpaced harness

- **Scope:** 11-perf (see [reference](../../reference/README.md))
- **Created:** 2026-09-24
- **Parent:** DA-115
- **Cost:** minor

## Evidence

Finding discovered while working on DA-115.

`RUNNER_ALLOWANCE` in `perf/budgets.ts` is 2.1 because CPU per frame, the line it is tuned to, has a budget of 9.5 ms against the 17.3 ms `ubuntu-latest` measured in DA-5.1: a CI ceiling of about 20, fifteen percent over the runner's reading ([11-perf.md](../../reference/11-perf.md), "The allowance is one multiplier, and it is tuned to one line").

DA-115 took the frame-rate limit off the harness, and the same code reads 0.5–0.9 ms a frame lower that way on the development machine (0.6 at the median of the day's paired comparisons, 11-perf.md "Where a run's time goes"). The owner kept the budget at 9.5 and the allowance at 2.1 on 2026-09-24, so the rule that moving the CPU-per-frame budget recomputes the multiplier is not triggered. But 17.3 is a 60 Hz reading, and no runner has run the unpaced harness: the run that landed DA-115 was local. If a runner comes down in the M1 Pro's proportion, 0.92–0.94, to about 16 ms, the ceiling of about 20 is about 24 % over it instead of 15 % — the looser CI gate DA-56.4 made the rule against. That is an assumption from one machine's shift, not a reading.

Nothing turns red either way, which is why this is minor: the ceiling can only have grown looser than intended, or stayed where it was.
