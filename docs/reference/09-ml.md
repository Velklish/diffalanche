# 09 · Model, index, and suggestions

**Nothing here is built.** `src/core/ml` does not exist, and no command, route,
or file of the data directory reads a model today. This page is here so the
reference has no gap in the middle and so the first task of Phase 2 has a place
to write into.

What is decided, and where the decision is:

| Subject | Where it is decided | Phase |
|---|---|---|
| The embedding model and how it is loaded | `docs/SPEC.md` sections 3 and 5 | 2 |
| The index over every session's comments | `docs/SPEC.md` section 7; `index rebuild` in section 8 | 2 |
| `suggest`: similar past comments and a likely severity | `docs/SPEC.md` section 8 | 2 |
| Suggestions in the composer while typing | `docs/design/HANDOFF.md` section 2 | 2 |
| How the model reaches the two delivery channels | `docs/SPEC.md` section 12, open question 1 | 2 |
| The generative model, `model pull` and `model status` | `docs/SPEC.md` section 8 | 4 |
| `insights`: recurring findings over past sessions | `docs/SPEC.md` section 8 | 4 |

The open question is delivery, and it is open on purpose: an embedding model is
tens of megabytes, the npm channel is a bundle of plain JavaScript, and the
binaries already carry the UI inside them. Downloading on first run and a
separate `@diffalanche/model` package are the two candidates; the owner decides
before Phase 2 starts (`docs/SPEC.md` section 12).

Until then, the vocabulary is reserved rather than used: *suggestion* is in
[the glossary](../GLOSSARY.md) with its phase marked, and `.diffalanche/` has no
index file in it. A comment written today carries everything an index would need
— body, severity, anchor, author — so Phase 2 indexes history rather than
starting from an empty one.
